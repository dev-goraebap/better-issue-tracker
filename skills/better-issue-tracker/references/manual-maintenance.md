# 사용 중인 매뉴얼 함께 갱신하기

이 절차는 BIT 스킬을 사용하는 에이전트가 프로젝트의 기능을 바꿀 때 실행한다. BIT 서버의 상시 감시·예약 작업을 만들거나 에이전트 밖에서 일어난 변경까지 자동 반영한다고 약속하지 않는다. [문서 작성](../playbooks/document.md)과 [매뉴얼 작성과 대조](manual-authoring.md)의 품질 기준을 그대로 따른다.

## 프로젝트별 적용 여부

세션에서 프로젝트를 확인할 때 아래 순서로 한 번 판정한다. 이미 확인한 설정/목록은 같은 세션에서 재사용한다.

1. 사용자가 매뉴얼 유지관리를 끄거나 프로젝트 지침에 미사용을 명시했다면 **비활성**이다. 매뉴얼을 만들거나 도입 여부를 반복해서 묻지 않는다.
2. 사용자 요청 또는 프로젝트 지침이 유지관리할 책을 지정했다면 **활성**이다. 지정된 워크스페이스·프로젝트·책만 대상으로 한다.
3. 명시적 설정이 없고 `list_manuals`를 사용할 수 있으면 현재 프로젝트의 매뉴얼 목록을 읽는다. 사용 중인 책이 있으면 **활성**, 없으면 **미사용**이다. 워크스페이스의 다른 프로젝트 책을 이 프로젝트의 대상으로 삼지 않는다. 워크스페이스 공통 책은 현재 프로젝트를 설명한다고 지정되거나 확인된 경우에만 포함한다.
4. 도구 없음·연결 실패·권한 부족이면 **확인 불가**다. 매뉴얼이 없다고 간주하지 않고 업무에 이유를 남긴다. 기능 작업 중 독립적으로 할 수 있는 일은 진행한다.

한 번 선택한 방식을 다음 세션도 따르게 하려면 프로젝트의 기존 에이전트 지침에 짧게 남긴다. 특정 제품의 설정을 배포 스킬에 고정하지 않는다. 예:

```markdown
## 매뉴얼 유지관리
- 이 프로젝트는 BIT 매뉴얼을 사용한다. 대상은 <워크스페이스> / <프로젝트 키> / <책 ID 또는 링크>다.
- 사용자에게 보이는 동작이 바뀌면 별도 요청 없이 관련 페이지와 필요한 사진을 갱신한다.
```

기존 책을 발견하면 자동으로 전체 재작성하지 않는다. 현재 기능을 설명하는 페이지부터 읽고 기존 구성·사용자 편집·다른 독자용 책의 범위를 보존한다.

## 기능 변경과 함께 할 일

1. **영향 페이지를 찾는다.** 업무와 연결된 기록, 책의 목차·본문, 이전 작성 근거를 확인한다. 업무에 직접 연결돼 있지 않아도 기능 이름·진입 위치·용어를 따라 관련 페이지를 찾는다. API의 제목 검색만으로 본문까지 검색했다고 가정하지 않는다.
2. **변경 전후를 대조한다.** 조작 순서·기본값·입력 길이/형식/첨부 제한·권한·상태·오류와 해결·표시 이름·결과·링크 중 달라진 것을 확인한다. 내부 리팩터링으로 사용자 동작이 같다면 갱신할 필요가 없다.
3. **같은 작업에서 갱신한다.** 바뀐 문장·조건표·관련 링크와 실제 모습이 달라진 사진을 수정한다. 활성인 책에 새 기능 설명이 없으면 기존 구성을 따라 페이지를 추가한다. 승인된 설명 깊이·사진 양식은 재승인받지 않는다. 제품 전체의 새 설명 체계나 공개 범위 변경은 이 자동 갱신에 포함하지 않는다.
4. **배포 시점을 맞춘다.** 운영 매뉴얼에는 운영에서 사용할 수 있는 기능을 설명한다. 아직 배포하지 않은 변경은 기존 작업의 검토 가능한 초안과 근거로 준비하고, 해당 버전 반영 때 게시할 항목을 남긴다. 운영 반영을 확인한 뒤 해당 페이지를 갱신한다. 개발 브랜치의 기능을 이미 운영에 있는 것처럼 설명하지 않는다.
5. **최신 본문을 보존하며 저장한다.** `get_manual`로 최신 책을 읽고 바뀐 부분만 반영한다. 서버 version을 사용하고409이면 새 사용자 편집과 내 변경을 합친다. 오래된 전체 책을 덮어쓰지 않는다. 권한이 없거나 촬영하지 못했다면 확인한 범위·남은 갱신을 업무에 남기며 완료라고 하지 않는다.
6. **작업 결과에 포함한다.** 바뀐 페이지 링크·확인한 기능/사진·기준 커밋 또는 버전·미검증 범위를 기능 업무의 결과 댓글에 남긴다. 활성 프로젝트에서 영향이 없으면 이유 한 줄이면 충분하다. 별도 매뉴얼 일지를 매 작업마다 만들지 않는다. 남은 갱신을 이번 작업에서 끝낼 수 없을 때만 후속 업무로 추적한다.

## 확인 예

| 상황 | 기대 행동 |
| --- | --- |
| 매뉴얼 비활성 또는 현재 프로젝트 책이 없음 | 기능 작업을 진행한다. 새 매뉴얼을 만들거나 사용을 권하지 않는다. |
| 활성 프로젝트의 업로드 한도가 바뀜 | 해당 작업의 제한표·오류 회복 설명을 갱신하고 실제 화면이 달라졌으면 재촬영한다. |
| 활성 프로젝트에서 내부 이름만 정리, UI/API 동작 동일 | 변경 범위를 대조하고 매뉴얼 영향 없음과 이유를 결과에 남긴다. |
| 다른 프로젝트의 책만 있음 | 그 책을 건드리지 않는다. |
| 최신 책에 사용자가 문장을 추가함 | 사용자의 문장을 보존하고 현재 변경에 필요한 부분만 고친다. |
| 변경 기능은 미배포 | 운영 설명은 유지하고 검토 가능한 초안을 기능 업무에 준비한다. 배포 반영 때 게시 여부를 확인한다. |

완료는 문서가 저장됐다는 사실뿐 아니라 변경한 기능과 해당 설명·조건·사진이 맞는지로 판단한다. 사용자가 실제로 요청한 범위를 넘어 새 책·예약 자동화·서비스 설정을 만들지 않는다.
