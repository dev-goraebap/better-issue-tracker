# 사용 중인 매뉴얼 함께 갱신하기

이 절차는 BIT 스킬을 사용하는 에이전트가 프로젝트의 기능·구조·개발 규칙을 바꿀 때 실행한다. BIT 서버의 상시 감시·예약 작업을 만들거나 에이전트 밖에서 일어난 변경까지 자동 반영한다고 약속하지 않는다. 사용자 문서는 [매뉴얼 작성과 대조](manual-authoring.md), 아키텍처·개발 문서는 [개발 매뉴얼 작성](development-manual.md)의 품질 기준을 따른다.

## 프로젝트별 적용 여부

세션에서 프로젝트를 확인할 때 아래 순서로 한 번 판정한다. 이미 확인한 설정/목록은 같은 세션에서 재사용한다.

1. 사용자가 매뉴얼 유지관리를 끄거나 프로젝트 지침에 미사용을 명시했다면 **비활성**이다. 매뉴얼을 만들거나 도입 여부를 반복해서 묻지 않는다.
2. 사용자 요청 또는 프로젝트 지침이 유지관리할 책을 지정했다면 **활성**이다. 지정된 워크스페이스·프로젝트·책만 대상으로 한다.
3. 명시적 설정이 없고 `list_manuals`를 사용할 수 있으면 현재 프로젝트의 매뉴얼 목록을 읽는다. 사용 중인 책이 있으면 **활성**, 없으면 **미사용**이다. 워크스페이스의 다른 프로젝트 책을 이 프로젝트의 대상으로 삼지 않는다. 워크스페이스 공통 책은 현재 프로젝트를 설명한다고 지정되거나 확인된 경우에만 포함한다.
4. 도구 없음·연결 실패·권한 부족이면 **확인 불가**다. 매뉴얼이 없다고 간주하지 않고 업무에 이유를 남긴다. 기능 작업 중 독립적으로 할 수 있는 일은 진행한다.

한 번 선택한 방식을 다음 세션도 따르게 하려면 프로젝트의 기존 에이전트 지침에 짧게 남긴다. 특정 제품의 설정을 배포 스킬에 고정하지 않는다. 예:

```markdown
## 매뉴얼 유지관리
- 이 프로젝트는 BIT 매뉴얼을 사용한다. 대상은 <워크스페이스> / <프로젝트 키> / <책 ID 또는 링크>다.
- 사용자에게 보이는 동작이 바뀌면 별도 요청 없이 관련 페이지와 필요한 사진을 갱신한다.
```

기존 책을 발견하면 자동으로 전체 재작성하지 않는다. 현재 기능을 설명하는 페이지부터 읽고 기존 구성·사용자 편집·다른 독자용 책의 범위를 보존한다.

## 기능 변경과 함께 할 일

프로젝트의 원본 방식을 먼저 확인한다. 저장소 원본을 지정한 프로젝트는 관련 로컬 원본을 읽고 코드 변경과 함께 갱신한다. 게시본을 읽는 MCP가 개발 규칙 접근의 필수 조건이 되지 않게 한다. 책만 발견했다고 기존 원격 원본을 임의로 저장소로 전환하지 않는다.

저장소 원본의 BIT 게시·충돌·자산·풍부한 블록 표현은 [게시 계약](manual-publication.md)을 따른다. 사용자 매뉴얼은 사용법/조건/권한/사진, 아키텍처는 구조/규칙/실제 예/검증 기준, 개발·관리 매뉴얼은 작업 순서/명령/회복을 대조한다. 원본을 여러 책에 복제하지 않는다.

기존 원격 원본 프로젝트는 전환이 승인될 때까지 관련 페이지를 선택 조회하고 최신 version과 사용자 편집을 보존하며 수정한다. 저장소 원본 프로젝트의 직접 원격 수정은 원본에도 반영해야 한다. 미배포 사용자 동작을 운영 사용법으로 먼저 게시하지 않는다. 관련 책이 없거나 비활성이면 매뉴얼을 강제하지 않는다.

완료 댓글에는 수정한 원본 경로·기준 리비전·게시 여부·대상 페이지·충돌/미지원/미검증 범위를 구분한다. 원본 변경만 하고 게시 완료라고 하지 않는다. 자동 게시·예약 작업이 실행되는 것으로 약속하지 않는다.
