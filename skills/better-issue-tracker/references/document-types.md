# 문서 유형

[문서 만들고 고치기](../playbooks/document.md)에서 고르는 유형의 프로필이다. 같은 유형이면 매번 같은 구성으로 쓴다. 독자는 기본값이고, 사용자가 다른 독자를 말하면 그것을 따른다.

## 제품설명서

- **기본 독자:** 제품을 처음 보는 사람이 도입하거나 맡을지 판단하려고 읽는다.
- **답할 질문:** 무엇이고 누구를 위한 것인가. 어떤 문제를 푸는가. 무엇을 할 수 있는가. 어떻게 쓰기 시작하는가. 무엇을 하지 않는가. 지금 어디까지 왔는가.
- **구성:** 한 문단 요약 → 푸는 문제 → 주요 기능(사용자가 하는 일 단위로) → 시작하는 법 → 하지 않는 것 → 지금 상태 → 문서 기준.
- **규칙:** 기능은 내부 구조가 아니라 사용자가 할 수 있는 일로 쓴다. 비교 대상(다른 제품)을 깎아내리지 않는다. 숫자(개수, 버전)는 팩트 시트에 있는 것만 쓴다.

## 사용자설명서

- **기본 독자:** 제품을 이미 쓰기로 한 사람이 한 가지 일을 해내려고 읽는다.
- **답할 질문:** 무엇을 하려면 어디서 무엇을 누르는가. 결과로 무엇이 보이는가. 막히면 어떻게 하는가.
- **구성:** 일 하나에 절 하나. 절마다 준비할 것 → 단계 → 결과 확인 → 막힐 때. 끝에 문서 기준.
- **규칙:** 단계는 번호를 붙이고 한 단계에 행동 하나. 화면의 글자는 화면에 보이는 그대로 따옴표로 쓴다. 단계를 실제 화면에서 따라 해 본 것만 쓴다.

## 인수인계

- **기본 독자:** 이 제품을 이어 맡을 개발자나 에이전트가 첫 작업 전에 읽는다.
- **답할 질문:** 어떻게 띄우고 검사하는가. 코드는 어떻게 나뉘는가. 꼭 지켜야 할 결정은 무엇인가. 지금 진행 중이거나 막힌 일은 무엇인가. 어디에 무엇이 기록되는가.
- **구성:** 띄우기와 검사 → 구조(폴더 지도) → 지켜야 할 결정(결정기록 참조 목록) → 진행 중인 일(업무 참조) → 기록이 있는 곳 → 문서 기준.
- **규칙:** 결정은 내용을 옮겨 적지 않고 결정기록 참조와 한 줄 요약만 쓴다. 명령은 실제로 돌려 본 것만 쓴다.
