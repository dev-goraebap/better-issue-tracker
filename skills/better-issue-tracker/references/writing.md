# 쓰는 말

- 본문과 댓글은 마크다운이다. 사람이 화면에서 읽는다고 생각하고 짧게 쓴다.
- 프로젝트 지침이 정한 언어로 쓴다. 정한 것이 없으면 사용자와 대화하는 언어로 쓴다.
- 비밀번호, API 키, 토큰, 개인정보는 업무에 쓰지 않는다.
- 하지 않은 일을 한 것처럼 쓰지 않는다. 확인하지 못한 것은 확인하지 못했다고 쓴다.
- 결정기록 본문은 [결정기록 틀](decision-template.md)을 따른다.
- 확인한 사실만 쓴다. 문서라면 팩트 시트에 없는 내용은 쓰지 않는다([문서 만들고 고치기](../playbooks/document.md)).

## 한국어로 쓸 때

AI가 쓴 티가 나는 글은 읽는 사람이 내용보다 말투에 걸린다. 아래는 자주 보이고 고치기 쉬운 것이다. 다른 언어로 쓸 때는 그 언어의 같은 버릇(번역투, 빈 수식어, 과한 높임)을 피한다.

| 버릇 | 나쁜 예 | 고친 예 |
| :--- | :--- | :--- |
| 빈 수식어 | 강력하고 효율적인 업무 관리 기능을 제공합니다 | 업무를 칸 다섯 개 중 하나에 두고 옮깁니다 |
| 번역투(~를 통해, ~에 대해, ~하는 것이 가능하다) | MCP를 통해 업무 생성이 가능합니다 | 에이전트가 MCP 도구 `create_work_item`으로 업무를 만듭니다 |
| '해당', '~ 시' | 해당 버튼 클릭 시 저장됩니다 | '저장'을 누르면 저장됩니다 |
| 글에 대한 글(메타 문장) | 이 섹션에서는 설치 방법에 대해 알아보겠습니다 | (지우고 바로 설치 방법을 쓴다) |
| 과한 높임, 이모지, 느낌표 | 꼭 확인해 주시기 바랍니다! 🚀 | 확인합니다. |
| '가지다'·'~의' 직역 | 작업은 담당자와 기한을 가집니다 | 작업에는 담당자와 기한을 정해요 |
| 사물이 주어인 문장 | 작업은 늘 다섯 범주 중 하나의 상태에 있습니다 | 작업의 상태는 다섯 가지예요 |
| 글에만 쓰는 말 | 결정과 업무를 한 흐름으로 잇습니다 | 결정과 업무가 서로 연결돼요 |
| 끝맺지 않은 명사 나열 | 일정은 참석자, 시각, 반복, 알림. | 일정에는 참석자와 시각을 정하고, 반복과 알림을 걸 수 있어요 |

한 문서 안에서 문체를 섞지 않는다. 제품 소개·사용자설명서처럼 사람에게 말을 거는 글은 '~해요'가 읽기 편하고, 기술 문서·인수인계는 '~합니다'나 '~한다'를 쓴다. 고른 것으로 끝까지 쓴다. 다 쓰고 나면 소리 내어 읽어 보고, 말로 하면 어색한 문장을 고친다.

## 결과 댓글의 예

```markdown
`a1b2c3d`에서 로그인 실패 시 남은 시도 횟수를 응답과 화면에 보이게 했습니다.

- 검증: 서버 테스트 통과, 로컬 화면에서 5회 실패까지 직접 확인
- 못 한 것: 운영 배포 전이라 실제 계정 잠금 메일은 확인하지 않음
```
