# 쓰는 말

- 본문과 댓글은 마크다운이다. 사람이 화면에서 읽는다고 생각하고 짧게 쓴다.
- 프로젝트 지침이 정한 언어로 쓴다. 정한 것이 없으면 사용자와 대화하는 언어로 쓴다.
- 비밀번호, API 키, 토큰, 개인정보는 업무에 쓰지 않는다.
- 하지 않은 일을 한 것처럼 쓰지 않는다. 확인하지 못한 것은 확인하지 못했다고 쓴다.
- '결정' 댓글은 [작업하는 동안](../playbooks/work.md)의 틀을 따른다.
- 확인한 사실만 쓴다. 문서라면 팩트 시트에 없는 내용은 쓰지 않는다([문서 만들고 고치기](../playbooks/document.md)).

## 문장과 구성

업무, 댓글, 문서 모두 사람이 화면에서 훑어본다. 구성이 보이면 내용이 읽히고, 구성이 없으면 길이와 상관없이 읽히지 않는다.

- **독자 한 명을 정한다.** 누가 읽고, 읽고 나서 무엇을 하려는지 먼저 정한다. 그 답이 깊이, 용어, 뺄 것을 정한다. 처음 보는 사람과 이미 아는 사람을 한 글에서 같이 챙기지 않는다.
- **한 문장에 생각 하나.** 쉼표가 두 개 넘게 필요하면 문장을 나눈다. 문단은 두세 문장이다.
- **순서가 있는 일은 번호 목록으로 쓴다.** 문장으로 이어 쓰지 않는다.
- **제목은 독자가 찾는 것으로 쓴다.** '개요', '배경 설명', '상세 내용' 같은 빈 제목을 달지 않는다. "로그인이 막힐 때"처럼 읽는 사람이 하려는 일이나 알려는 것을 쓴다. 제목 단계를 건너뛰지 않는다.
- **용어는 하나로 쓴다.** 같은 것을 '업무', '작업', '이슈'로 섞어 부르지 않는다. 화면과 도구에 있는 이름을 그대로 쓰고, 처음 나오는 낯선 말은 그 자리에서 한 구절로 풀어 쓴다.
- **꾸미지 않는다.** '강력한', '손쉬운', '혁신적인'으로 평가하지 말고, 무엇을 하는지 쓴다.
- **아는 동료가 옆에서 설명하듯 쓴다.** 공문 말투도, 광고 말투도 아니다.
- **짧은 글에는 제목을 달지 않는다.** 대여섯 줄이 안 되는 댓글은 문단과 목록이면 된다. 업무 설명은 [업무 만들기](../playbooks/create.md)의 틀에 있는 제목을 그대로 쓴다.

글을 쓴 뒤 처음 보는 사람의 눈으로 다시 읽는다. 무엇을 하라는 글인지, 무엇이 끝났다는 글인지 첫 두 줄에서 알 수 없으면 첫 두 줄을 고친다.

## AI가 쓴 티가 나는 구성

말투만큼 구성도 티가 난다. 아래가 보이면 고친다.

| 버릇 | 고치는 법 |
| :--- | :--- |
| 모든 줄을 "**이름:** 설명" 꼴로 씀 | 그 줄들이 한 가지 이야기면 문장으로 잇는다. 정말 항목이면 이름 없는 목록으로 쓴다 |
| 굵은 글씨가 문단마다 여럿 | 한 글에서 꼭 먼저 봐야 할 것 한두 곳에만 쓴다 |
| 무엇이든 세 개씩 나열 | 실제로 있는 만큼만 쓴다. 하나면 하나다 |
| 끝에 "정리하면", "요약하면"으로 앞 내용을 되풀이 | 지운다. 첫 문단이 이미 요약이어야 한다 |
| 내용이 한 줄인 표, 열이 하나인 표 | 문장이나 목록으로 바꾼다. 표는 두 가지 이상을 같은 기준으로 비교할 때 쓴다 |
| 영어식 긴 줄표(—), 머리표 대신 이모지 | 마침표로 문장을 끊는다. 머리표는 `-`만 쓴다 |
| 질문으로 단 제목("왜 필요할까요?") | 답을 제목으로 쓴다("업무가 늘어나는 이유") |

## 한국어로 쓸 때

AI가 쓴 티가 나는 글은 읽는 사람이 내용보다 말투에 걸린다. 아래는 자주 보이고 고치기 쉬운 것이다. 다른 언어로 쓸 때는 그 언어의 같은 버릇(번역투, 빈 수식어, 과한 높임)을 피한다.

| 버릇 | 나쁜 예 | 고친 예 |
| :--- | :--- | :--- |
| 빈 수식어 | 강력하고 효율적인 업무 관리 기능을 제공합니다 | 업무를 칸 다섯 개 중 하나에 두고 옮깁니다 |
| 번역투(~를 통해, ~에 대해, ~하는 것이 가능하다) | MCP를 통해 업무 생성이 가능합니다 | 에이전트가 MCP 도구 `create_work_item`으로 업무를 만듭니다 |
| '해당', '~ 시' | 해당 버튼 클릭 시 저장됩니다 | '저장'을 누르면 저장됩니다 |
| 글에 대한 글(메타 문장) | 이 섹션에서는 설치 방법에 대해 알아보겠습니다 | (지우고 바로 설치 방법을 쓴다) |
| 과한 높임, 이모지, 느낌표 | 꼭 확인해 주시기 바랍니다! 🚀 | 확인합니다. |
| '가지다'·'~의' 직역 | 작업은 담당자와 기한을 가집니다 | 작업에는 담당자와 기한을 정해요 |
| 사물이 주어인 문장 | 작업은 늘 다섯 범주 중 하나의 상태에 있습니다 | 작업의 상태는 다섯 가지예요 |
| 글에만 쓰는 말 | 결정과 업무를 한 흐름으로 잇습니다 | 결정과 업무가 서로 연결돼요 |
| 끝맺지 않은 명사 나열 | 일정은 참석자, 시각, 반복, 알림. | 일정에는 참석자와 시각을 정하고, 반복과 알림을 걸 수 있어요 |

한 문서 안에서 문체를 섞지 않는다. 제품 소개·사용자설명서처럼 사람에게 말을 거는 글은 '~해요'가 읽기 편하고, 기술 문서·인수인계는 '~합니다'나 '~한다'를 쓴다. 고른 것으로 끝까지 쓴다. 다 쓰고 나면 소리 내어 읽어 보고, 말로 하면 어색한 문장을 고친다.

## 결과 댓글의 예

```markdown
`a1b2c3d`에서 로그인 실패 시 남은 시도 횟수를 응답과 화면에 보이게 했습니다.

- 검증: 서버 테스트 통과, 로컬 화면에서 5회 실패까지 직접 확인
- 못 한 것: 운영 배포 전이라 실제 계정 잠금 메일은 확인하지 않음
```
