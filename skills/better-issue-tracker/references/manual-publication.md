# 저장소 원본과 BIT 게시 계약

## 현재 기능과 설계 범위

저장소의 Markdown/자산이 원본이며 BIT는 독자용 게시본이다. SKILL.md는 작업을 고르는 입구이고 references 또는 docs의 원본을 선택해 읽는다. 현재 BIT MCP의 페이지 body는 Markdown이다. 아래 풍부한 블록 계약은 향후 게시 어댑터 설계이며 Tiptap JSON 게시·자동 동기화·3방향 병합을 구현했다고 말하지 않는다. 별도 에디터 코드를 이 작업에서 변경하지 않는다.

## 원본 구성과 소유권

프로젝트별 게시 manifest에는 formatVersion, 저장소 식별자, 책 key/대상 ID, 섹션 순서, 페이지 key/경로/대상 ID/소속, 자산 참조를 둔다. key는 제목·배열 위치와 독립적이며 이름 변경에도 유지한다. 비밀값과 개인 절대경로를 넣지 않는다. 코드 예의 근거는 저장소·경로·리비전으로 표시한다. 멀티레포의 공통 계약은 소유 저장소 하나를 지정하고 소비자는 참조한다. 책의 개수로 스킬 수를 정하지 않는다.

게시 상태는 편집 원본과 별개로 sourceRevision, sourceHash, adapterVersion, targetVersion, lastPublishedBodyHash 및 원본 블록 key와 대상 ID 매핑을 저장하도록 설계한다. Git 커밋 전 해시와 커밋 이후 리비전을 혼동하지 않는다. 현재 서버가 이 메타데이터를 저장한다고 가정하지 않는다. 원격 본문/자산은 최초 이관 때 최신 값을 읽어 보존하고 이관 이후의 직접 편집을 무시하지 않는다.

## 게시 절차

1. 기능 변경 시 로컬 관련 원본과 사진/근거를 코드와 함께 갱신한다. 네트워크가 없어도 개발 규칙을 읽을 수 있어야 한다. 게시 실패를 로컬 개발 불가능으로 만들지 않는다.
2. 원본을 해석하고 링크·자산·지원하지 않는 표현을 검사해 변경 계획을 만든다. 사용자 사용법은 운영 배포 기준으로 게시하고 미배포 내용은 원본의 초안으로 유지한다. 원본 경로·기준 리비전이 없는 게시를 완료로 보고하지 않는다.
3. 현재 Markdown 도구로 지원되는 표현만 게시한다. 수정 직전 get_manual_page의 최신 본문/version을 읽는다. 마지막 게시 기준이 없으면 원본과 원격의 차이를 먼저 검토해 기준을 확립한다. 최신 원격이 마지막 게시본과 다르면 자동 덮어쓰지 않고 원본에 사용자 편집을 반영하거나 충돌로 남긴다. expected_version은 낙관적 잠금이며 직접 편집 탐지를 대신하지 않는다.
4. 페이지 수정에는 update_manual_page를 사용하고 댓글·관련 없는 페이지/속성은 건드리지 않는다. 409이면 최신 원격을 다시 읽어 계획을 재검토한다. 전체 책 교체는 전체 상태가 필요한 작업에만 사용한다. 댓글은 원본 개선 의견으로 취급하고 해결을 임의로 표시하지 않는다.
5. 저장 후 본문·이미지·링크를 확인하고 기준 리비전·대상 version·미지원 요소·검증 결과를 업무에 남긴다. 같은 해시 재게시는 변경 없음이어야 한다. 부분 실패 시 성공한 페이지를 무작정 재작성하거나 신규 페이지를 중복 생성하지 않는다. 삭제는 별도 계획으로 검토하며 원본에서 사라졌다는 이유만으로 원격 자료를 자동 삭제하지 않는다.

## 풍부한 블록을 위한 중간 표현 (설계)

Markdown은 기본 저작 형식이다. 일반 구문으로 표현할 수 없는 의미는 명시적인 확장 구문 또는 페이지별 구조화 sidecar에 둔다. 표현 문법과 JSON Schema를 확정하기 전 임의의 구문을 구현된 형식처럼 게시하지 않는다. 에이전트가 읽을 텍스트 대체 표현을 함께 제공하고 원본 정보가 없는 레이아웃을 추측하지 않는다.

| 원본 의미 | 중간 표현과 게시 대상 |
| --- | --- |
| 제목·문단·목록·인용·코드 | type, 안정적 key, attrs, 자식, 텍스트/mark. 지원되는 Markdown 블록으로 게시 |
| 콜아웃·토글·열 | 명시적인 type/중첩 children/열 구성. target capability 확인 후 전용 블록으로 변환 |
| 표·병합 셀 | 행/셀 key, colspan/rowspan/header 속성. 일반 Markdown 표로 조용히 축소 금지 |
| Mermaid·수식 | 원문·언어/표시 모드 보존. 호스트 렌더러 어댑터로 연결 |
| 이미지·동영상·음성·첨부 | 저장소 상대 asset key, MIME/hash, alt/설명, 크기 속성. 업로드 완료 ID와 매핑 |
| 웹 임베드 | 명시적 URL과 사용자 로드 정책. 게시만으로 외부 콘텐츠 자동 실행 금지 |
| 색·폰트·정렬 | 의미상 필요한 속성과 테마 장식을 구분. 테마는 호스트가 담당 |

중간 표현 schemaVersion과 대상 editorSchemaVersion, 지원 node/mark/attrs 목록을 교환하는 어댑터를 둔다. 스킬 원본을 특정 Tiptap 내부 JSON 버전에 직접 묶지 않는다. 미지원/알 수 없는 블록·속성은 원본을 보존하고 위치/key와 이유를 오류 또는 명시적인 대체 제안으로 반환한다. 손실되는 변환은 자동 게시하지 않는다. 문서 기본 읽기/Undo/선택·블록 이동은 에디터 책임이며 게시 변환기의 책임이 아니다.

## 검증 기준

기본 Markdown 및 토글/콜아웃/중첩 열/병합 표/수식/Mermaid/미디어/미지원 노드 fixture로 의미·순서·key·자산 참조 보존을 검증하도록 한다. 게시 재실행의 멱등성, 원격 편집 충돌, 409, 부분 실패, 업로드 실패와 고아 자산, 댓글 보존, 원본 키 변경/페이지 이동을 확인한다. 읽기 화면·PDF/Markdown 내보내기의 표현 한계도 명시한다. 이는 구현 시 필요한 검사 기준이며 현재 통과한 검사 목록이 아니다.
