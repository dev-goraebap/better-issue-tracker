# 프로젝트별 개발 스킬 구성하기

사용자가 프로젝트 스킬 생성·정리나 매뉴얼 연결을 요청했을 때 사용한다. 매뉴얼 도입만으로 스킬을 자동 생성하지 않는다. 기존 에이전트 지침과 사용자 편집을 먼저 확인한다.

## 범위와 원본 확인

1. 현재 저장소의 AGENTS.md, 설치 스킬, 패키지/빌드/CI, 실행 스크립트를 확인한다. Git 원격과 작업 디렉터리로 저장소를 식별하며 제품 이름만으로 같은 저장소라고 추정하지 않는다. 다른 저장소는 실제 접근 가능한 범위만 조사한다.
2. BIT 워크스페이스·프로젝트와 사용하는 매뉴얼을 확인한다. 사용자 매뉴얼은 사용법, 프로젝트 관리/개발 매뉴얼은 작업 절차, 아키텍처 매뉴얼은 구조·설계 규칙·실제 예·검증 기준을 맡는다. 기존 책의 목적과 이름을 보존하며 세 책을 강제로 만들거나 책마다 스킬을 만들지 않는다.
3. 기존 스킬의 규칙·절차·도구·참조를 분류한다. 상세 규칙은 저장소의 아키텍처 원본으로, 수행 절차는 관리/개발 원본으로 모으고 BIT에는 게시한다. 기존 원격 편집을 최신 조회해 보존한 뒤 단일 원본을 확립한다. 폐기할 지침은 현재 코드와 충돌하는 이유를 업무에 남긴다. 실행 스크립트, 외부 스킬 연결, 배포 권한 경계는 보존한다.

## 저장소 구성과 이름

- 기존 진입 스킬이 있으면 우선 수정한다. 새 이름은 기본 `<project>-development`; 소문자·숫자·하이픈을 쓰고 실제 제품 식별자를 사용한다. 무의미하게 `skills`를 덧붙이지 않는다. 이름 변경은 호출자·AGENTS·검사·동기화 설정·설치 사본까지 함께 맞춘다.
- 모노레포는 한 진입 스킬에서 경로/작업별로 필요한 로컬 원본과 명령을 선택한다. 독립적인 작업 경계가 필요할 때만 하위 스킬로 나눈다.
- 멀티레포는 각 저장소에 `<project>-frontend-development`, `<project>-backend-development`처럼 범위가 분명한 진입점을 둔다. 저장소 이름이 이미 고유하면 그것을 사용한다. 같은 제품의 공통 계약의 원본 소유 저장소를 지정하고 게시 매뉴얼은 하나로 참조하고, 각 진입점에는 공통 페이지와 해당 저장소 페이지의 연결만 둔다. BIT 프로젝트를 저장소 개수만큼 복제하지 않는다. 조직이 이미 여러 BIT 프로젝트로 관리하면 그 관계를 확인해 따른다.
- 저장소 지도에는 저장소 식별자/담당 범위/로컬 확인 여부/관련 페이지/계약 원본을 기록한다. 이식 가능한 경로를 사용하고 개인 절대 경로·토큰을 저장하지 않는다.
- API·이벤트·스키마 변경은 제공자와 소비자 저장소의 영향도 확인한다. 접근할 수 없는 저장소는 확인하지 않았다고 밝히고 후속 작업을 연결한다. 다른 저장소를 수정·배포할 권한이 생겼다고 간주하지 않는다. 근거 코드는 저장소·경로·리비전으로 식별한다.

## 진입점에 남길 내용

스킬 description에는 이 저장소의 코드/설정/검증 작업이라는 트리거를 담는다. 본문에는 워크스페이스·프로젝트, 저장소 담당 범위, 작업별 로컬 원본 경로와 게시 대상 지도, 공용 BIT 스킬과 필요한 도구 연결만 둔다. SKILL.md에 상세 본문을 넣지 않고 references 또는 docs의 로컬 원본을 선택해 읽는다. 원본 없이 원격 링크만 남기지 않는다. 배포하는 공용 스킬에는 특정 프로젝트 ID를 고정하지 않는다.

페이지 선택·최신 version·충돌·사용자 편집 보존·미배포 기능 처리는 [매뉴얼 유지관리](../references/manual-maintenance.md)를 따른다. 연결 실패 시 이유를 알리고 코드·검사·저장소 지침으로 확인 가능한 범위를 진행한다. 기억으로 원격 규칙을 꾸며내지 않는다. 필요하면 추적 가능한 저장소 계약/결정 원본을 읽는다.

## 검증과 완료

- 작업별 지도에서 각 책/페이지 ID와 저장소 범위가 맞는지 실제 조회한다. 전체 책 탐색 응답은 재사용한다.
- 이름 변경 전후의 호출자와 설치 사본을 검색하고 상대 링크·스크립트 실행 경로를 검사한다. 새 폴더에서 스크립트를 실행해 경로 계산도 확인한다.
- 모노레포 작업 한 가지와 멀티레포 계약 변경 한 가지를 대입해 필요한 페이지, 수행 저장소, 권한/접근 한계를 설명할 수 있어야 한다.
- 이관한 규칙/남긴 도구/폐기한 옛 지침과 미확인 범위를 해당 업무에 기록한다. 스킬 설치·동기화가 다른 프로젝트의 자동 업데이트나 운영 배포를 의미하지 않는다.

저장소 원본의 게시와 풍부한 블록 호환성은 [게시 계약](../references/manual-publication.md)을 따른다. 실제 게시 어댑터 미구현 범위는 명확히 구분한다.
