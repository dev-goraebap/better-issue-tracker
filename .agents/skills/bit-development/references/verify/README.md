# BIT 검증 지도

사용자에게 보이는 BIT 동작을 확인하는 원본이다. 조작 전에 이 색인을 읽고, 맞는 기능 파일을 절차로 쓴다.

## 기본 준비

- `verify launch <run>`으로 띄운 run이다. 출력의 `client`(예: `http://127.0.0.1:51721`)가 화면 주소다.
- 첫 관리자(`account.json`), 워크스페이스 `verify-<run>`, API 키가 있다. 프로젝트와 업무는 없다.
- `verify doctor <run>`이 `"ok": true`다.
- 이 run이 띄우지 않은 BIT는 조작하지 않는다.

## 조작 규칙

- 별도 조건이 없으면 기본 준비 상태에서 시작한다.
- 화면은 보이는 이름(버튼 글, `aria-label`, 입력칸 placeholder)으로 찾는다. 좌표와 DOM 순서에 기대지 않는다.
- 명령은 적힌 그대로 쓴다. 따옴표 안 이름과 인자를 바꾸지 않는다.
- 바꾼 데이터는 run을 정리하면 함께 사라진다. 증거는 남는다.

## 증거와 건너뜀 보고

- 조작과 그 결과 상태를 함께 남긴다. 마지막 화면만으로는 증거가 아니다.
- 바꾼 값은 다른 길(DB 읽기 또는 화면)로 한 번 더 본다.
- 증거마다 기능 ID와 쓴 입구를 이름에 넣는다(`--save work-item-move-mcp`).
- 닿지 못한 길은 시도한 명령과 못 맞춘 조건으로 보고한다. 다른 길로 대신 확인하고 그 길을 확인했다고 하지 않는다.
