이 문서는 BIT 전반의 아키텍처 원칙, 시스템 제약, 컴포넌트 구조, 런타임 흐름 및 운영 기준을 정의하는 최상위 가이드다.
세부 기술 표준은 백엔드·프론트엔드·API와 공통 계약 지침을, 결정의 맥락은 `docs/decisions.md`를 원본으로 참조한다.

## 1. 소개와 목표

사람과 에이전트가 남긴 세션·결정·산출물·작업항목·코드를 하나의 흐름으로 잇는 설치형(Self-hosted) 경량 ALM이다 (`docs/01-vision.md`).
- **핵심 흐름**: `트리거 → 결정 → 작업항목 → 변경(문서 개정·커밋) → 완료`가 끊기지 않게 잇는다 (`docs/02-domain-model.md`).
- **품질 우선순위**: 에이전트가 1순위 사용자(API·MCP 먼저, UI는 그 위에), 가벼움(Kaneo 수준), "왜"의 추적성, 외부 기능 없이도 실행됨, 모바일·데스크톱 적응형 사용성.
- **설정 분리**: 프로젝트·워크스페이스 운영 값은 사용자 설정으로, 스토리지·메일·Git 토큰 등 자격 증명은 운영 환경 설정으로 분리한다.

## 2. 아키텍처 제약

- **모노레포 및 빌드**: 단일 저장소 내에서 `server`(Java 21/Gradle)와 `client`(React/Vite/npm)를 독립적으로 빌드한다.
- **클라이언트 CSR**: 프론트엔드는 100% CSR SPA로 동작하며 SSR·SSG를 배제하고, 서버(Spring Boot)가 정적 빌드 자산을 API와 함께 서빙한다.
- **백엔드 스택**: Java 21, Spring Boot, jOOQ, Flyway, SQLite(파일 하나)를 사용하며, 도메인 모델은 프레임워크 비의존적인 순수 Java로 유지한다 (D-010).
- **배포 인프라**: 화면과 서버를 이미지 하나(저장소 루트 `Dockerfile`)로 만들어 컨테이너 하나로 띄운다. 앞단 프록시를 두면 TLS와 전달만 맡긴다. 수평 확장·무중단 배포를 전제하지 않는다. DB가 SQLite 파일 하나라 쓰기는 한 곳에서만 일어나며, 인스턴스는 한 대로 운영한다.
- **Git hosting은 만들지 않는다**: Git은 소유가 아니라 참조다. 커밋·MR은 웹훅으로, md 정본은 저장소별 읽기 전용 토큰으로 호스팅 API에서 읽는다 (D-003, D-028). 컨테이너에 git을 넣지 않는다.
- **데이터 보안**: 실제 사용자 데이터와 비밀값은 코드베이스나 시드 데이터에 넣지 않는다.

## 3. 컨텍스트와 범위

### 사용자 역할별 범위
| 사용자 역할 | 주요 업무 범위 |
| :--- | :--- |
| **인스턴스 관리자** | 첫 가입자(D-009). 사용자·임시 비밀번호 발급(D-027), 선택 기능의 연결 상태 확인 |
| **워크스페이스 멤버** | `owner`·`admin`·`member`·`viewer` 4개 고정 역할. 프로젝트·작업항목·결정·세션·문서함 사용 |
| **에이전트** | 별도 계정 없이 사람의 API 키(Bearer)로 REST·MCP 호출. 키의 `agent_name`이 기록에 남는다 (D-021) |
| **운영자** | 컨테이너·데이터 볼륨·환경 설정, 백업·복구 |

### 외부 연동 경계
- 외부 연동은 메일(SMTP), Git 호스팅(웹훅·읽기 API), S3 호환 스토리지로 한정한다. 문서 텍스트 변환(D-031)과 PDF 생성(D-032)은 서버 안 어댑터다.
- 외부 제공자 장애가 작업항목·결정 조회 같은 핵심 기능의 장애로 번지지 않게 트랜잭션 밖 비동기 처리로 격리한다.

## 4. 솔루션 전략

- **모듈형 모놀리스(Modular Monolith)**: 단일 배포 안에서 애그리거트 소유권에 따라 모듈을 엄격히 분리한다.
- **명령과 조회의 분리**: 변경은 도메인 모델과 `Repository.save()` 단일 진입점을 거치고, 화면 조회는 jOOQ로 화면 DTO에 직접 투영한다.
- **API·MCP 먼저**: 기능은 REST와 MCP로 먼저 열고, 화면은 그 위에 올린다 (D-006). MCP는 인스턴스 내장 HTTP `/api/mcp` 하나다 (D-022).
- **선택 기능은 어댑터로 (D-030)**: 외부에 기대는 기능(메일, Git 연동, 파일 저장소, 문서 텍스트 변환, PDF 생성)은 인터페이스 + 어댑터로 나눈다.
  - 설정이 없거나 연결이 안 되면 그 기능만 꺼지고 서버는 정상 기동한다.
  - 서버는 켜진 기능 목록을 API로 알려 주고, 화면은 그 값을 보고 버튼을 숨긴다. MCP 도구는 꺼진 기능이면 이유를 오류로 돌려준다.
  - 예외: 파일 저장소는 로컬 어댑터가 내장되어 기본으로 켜져 있다. S3 호환(AWS S3·R2·MinIO)은 설정으로 바꾼다 (D-029).
- **프론트엔드 상태 분리**: 서버 데이터(TanStack Query), 라우트 파라미터(TanStack Router), 폼 입력 초안(Local State)으로 소유권을 나눈다.
- **타입 계약 동기화**: 서버 OpenAPI 스펙(`server/openapi.json`)으로 클라이언트 TypeScript 타입을 자동 생성한다.

## 5. 구성 요소와 의존성

### 저장소 디렉터리 구조
```text
server/            Gradle 백엔드 API 애플리케이션
client/            React CSR 프론트엔드 (OpenAPI 자동 생성 타입 포함)
docs/              명세·결정 기록 (도그푸딩 전까지의 원본, D-023)
deploy/            compose 파일
scripts/           sync-skills.mjs 등
.agents/skills/    에이전트 스킬 원본
Dockerfile         3단계 빌드 (node → jdk → jre)
dev.sh             로컬 실행
```

### 프론트엔드 (Feature-Sliced Design)
- 참조 방향: `app → pages → widgets → features → entities → shared`
- 슬라이스 외부는 공개 `index.ts`로만 참조하며, 같은 레이어의 다른 슬라이스를 직접 참조하지 않는다.

### 백엔드 (모듈 구조)
- 패키지 루트: `io.github.goraebap.bit` 아래 `module/<업무>`와 `shared/<기반>/`로 나눈다. 컨텍스트 그룹은 두지 않고 모든 모듈을 `module/` 바로 아래에 둔다.
- 모듈: `iam`, `workspace`, `project`, `workitem`, `decision`, `session`, `artifact`, `coderef`, `link`, `file`, `notification` (`docs/06-schema.md`).
- 모듈 내부 계층: 공개 루트 계약, `application`(Controller, Service, Query), `domain`(Entity, Value Object, Repository 포트), `infrastructure`(jOOQ 구현체 `Jooq*Repository`, 외부 어댑터. package-private).
- 모듈 간 참조: 공개 계약(`*Facade`, `*Spi`, `*Event`)으로만 통신하고, 애그리거트 간에는 객체 대신 ID로 참조한다. 순환 참조는 금지한다. ArchUnit(`ArchitectureTest`)이 강제한다.
- 문서에서 정해진 의존 방향:
  - MCP는 업무를 소유하지 않는다. MCP 도구는 각 모듈의 Facade를 직접 부르고 REST API를 다시 부르지 않는다 (`docs/07-mcp.md`).
  - `artifact`는 정본·파생본을 `file`의 `blob`으로 가리킨다. 다른 모듈의 첨부도 `file`의 `attachment`로 붙인다.
  - `link`는 만들 때 대상(작업항목·결정·세션·산출물·코드 참조)이 있는지 검사한다 (D-014).
- 선택 기능 어댑터(D-030)는 기능을 쓰는 모듈의 `infrastructure`에 두고, 포트는 그 모듈 또는 `shared`에 둔다.

## 6. 런타임 흐름

- **화면 조회**: 앱 초기화 → 세션 확인 → 라우트 권한 검증 → TanStack Query 캐시 확인 및 서버 조회 → 렌더링.
- **명령 처리**: 폼 입력 → 클라이언트 검증 → 서버 요청 → 인증·권한 검증 → 트랜잭션 내 불변식 평가 → `Repository.save()` → 관련 Query 키 무효화·재조회.
- **에이전트 호출**: MCP `/api/mcp` → API 키 인증(키 주인의 워크스페이스 역할로 판정) → 모듈 Facade → 기록에 `agent_name`을 남긴다 (D-021, D-022).
- **파일 업로드와 변환**: 사전 서명 PUT 직접 업로드 → 업무 모듈이 권한 확인 후 확정 → 크기·MIME 검증. 문서 텍스트 변환(D-031)과 PDF 생성(D-032)은 트랜잭션 밖 작업으로 돈다.
- **Git 웹훅**: 수신 → 커밋을 코드 참조로 기록하고 작업항목과 `implements`로 잇는다 → 바뀐 md만 호스팅 API로 받아 산출물 현재 내용을 갱신한다 (D-028). 받은 뒤 처리는 트랜잭션 밖에서 한다.

## 7. 배포와 운영

- **이미지**: 루트 `Dockerfile`이 화면 빌드(Node 24) → 서버 jar(JDK 21) → 실행 이미지(JRE 21) 순서로 만든다. 비루트 사용자로 돌고, HEALTHCHECK는 `/api/v1/health`다(DB를 읽으므로 기동과 연결을 함께 알린다).
- **화면 서빙**: 서버가 이미지 안 화면 파일을 서빙한다. `/api/`가 아니고 파일도 아닌 주소는 `index.html`, 마지막 조각에 확장자가 있는 주소는 404. `/assets/`는 1년 불변 캐시, 나머지 `no-cache`. 로그인 확인은 `/api/`에만 건다. 응답 압축은 앱 서버가 한다(프록시가 아니다).
- **데이터**: 볼륨 하나(`/var/lib/bit`)에 SQLite DB(`bit.db`)와 로컬 파일 저장소를 둔다. 백업 대상은 이 볼륨이다.
- **실행과 CI**: 로컬은 `sh dev.sh`(Docker 없음). 컨테이너 실행은 compose. CI는 GitHub Actions가 서버 `./gradlew check`, 화면 `npm run check`를 검사하고, 태그에서 이미지를 만든다. 배포 자동화는 나중이다 (D-026). 절차는 [배포](references/deploy.md).
- **환경 변수 및 보안**: 자격 증명은 환경 변수로 주입한다. 선택 기능 설정이 비면 그 기능만 끈다(D-030). 비밀값(인증 비밀키·스토리지 키·SMTP 비밀번호·Git 토큰)은 관리자 화면에서 보이거나 바꾸지 않는다. 화면에는 값 없이 연결 상태(설정됨·없음)만 보인다. 저장소별 Git 토큰은 암호화해 DB에 둔다 (D-028).
- **데이터베이스 운영**: 배포된 Flyway 마이그레이션은 수정하지 않고 새 마이그레이션으로 교정한다. DB와 파일 저장소 백업을 병행한다. SQLite 파일(WAL 포함)이 백업 대상이다. SQLite 설정(WAL, `synchronous=NORMAL`, `busy_timeout=5000`)은 Litestream 요구와 맞으며 서버는 체크포인트를 직접 하지 않는다. 연속 복제는 Litestream(선택)으로 한다.

## 10. 품질 기준과 검증

- **백엔드 검증**: Spotless, Checkstyle, SpotBugs, ArchUnit, 실제 SQLite 파일 통합 테스트(파일은 로컬 폴더 저장소). Docker를 쓰지 않는다. `./gradlew check`가 완료 기준이다.
- **프론트엔드 검증**: Steiger, TypeScript 타입 검사, 컴포넌트 린트, 테스트, Vite 프로덕션 빌드. `npm run check`가 완료 기준이다.
- **핵심 품질 시나리오**: 권한 없는 대상 접근 차단(404/403 모호화), 상태 전이 동시 요청의 멱등성, 악성 SVG·파일 업로드 차단, 세션 만료 시 브라우저 캐시 파기, 선택 기능 설정이 모두 비어도 서버 기동·해당 버튼 숨김.

## 11. 위험 관리와 기술 부채

- **동시성 제어**: 클라이언트 캐시에 기대지 않고 DB 쓰기 잠금, 낙관적 락 버전, 유니크 인덱스로 서버에서 제어한다. 모든 트랜잭션은 시작할 때 쓰기 잠금을 잡으므로(`BEGIN IMMEDIATE`) 쓰기가 차례로 일어나고, 읽기는 WAL 덕분에 막히지 않는다. 그래서 트랜잭션 안에서는 메일·Git API·문서 변환·PDF 생성 같은 느린 호출을 하지 않는다.
- **비동기 자원 정리**: 확정되지 않은 업로드와 삭제된 엔티티의 고아 파일은 백그라운드 GC 배치로 정리한다.
- **외부 연동 장애 격리**: 메일 발송과 Git 호스팅 호출은 트랜잭션 밖에서 처리한다. 실패해도 그 기능만 실패하고 앱 전체는 멈추지 않는다 (D-030).

## BIT에서 정할 것

- 모듈 간 의존 방향 중 문서에 없는 것(예: `decision`↔`workitem`, `coderef`↔`workitem`, `notification`을 누가 부르나). 정하면 `ArchitectureTest` 규칙과 이 절을 같이 고친다.
- MCP 어댑터의 패키지 위치(모듈인지 `shared`인지)와 실시간 변경(SSE)을 맡는 곳.
- 업무 기준 시간대(SandboxHr는 `Asia/Seoul` 고정, 이미지 `TZ` 포함). 개인 셀프호스팅이라 설정으로 둘지.
- 일부만 채운 선택 기능 설정(예: SMTP 주소만 있고 비밀번호 없음)을 기동 실패로 볼지, 기능 꺼짐으로 볼지.
- 운영 비밀값(`AUTH_SECRET` 등)을 첫 기동 때 자동 생성해 볼륨에 둘지.
- 시스템 현황·로그 DB(SandboxHr `logs.db`)를 둘지.
