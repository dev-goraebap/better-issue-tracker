# 스킬 수선

BIT의 작업 방식은 `.agents/skills/`의 스킬이 원본이다. 결과가 틀리면 대화에서 결과만 바로잡지 않고, 그 결과를 낸
스킬을 고쳐 다음 작업이 처음부터 맞게 한다. 스킬은 앞으로의 작업 규칙이므로 수정은 초안을 보여 주고 승인을 받은 뒤
적용한다.

## 스킬의 구조

```text
.agents/skills/<이름>/
  SKILL.md      언제 쓰나, 절차, 판단 규칙, 완료 기준, 과거 예외
  references/   절차가 가리키는 세부 문서
  scripts/      기계적인 단계를 대신하는 스크립트
  notes.md      수정 기록, 최신이 위
```

| 층 | 무엇 | 지킬 것 |
| --- | --- | --- |
| 절차 | `SKILL.md` | description은 실제로 할 요청 문구를 담는다. 판단마다 근거 한 줄. 마지막 줄에 "결과가 틀리면 `skill-repair`로 이 스킬을 고친다" |
| 도구 | `references/`, `scripts/` | 목적당 파일 하나. 파일 이름에 날짜·버전을 넣지 않는다. 비밀값과 일회성 결과물은 두지 않는다 |
| 검증 | `SKILL.md`의 완료 기준 | 반증할 수 있는 확인만 쓴다(실행할 명령, 같은 커밋에 있어야 할 파일). "깔끔하게" 같은 인상 표현은 기준이 아니다 |

- 예시가 필요하면 저장소의 실제 파일 경로를 가리킨다. 코드를 복사해 두면 코드가 바뀔 때 낡는다. 글로 된 결과물(커밋
  메시지 등)만 예시 파일을 둔다.
- 제품·설계와 작업 규칙을 왜 그렇게 정했는지는 `docs/decisions.md`(D-023), 프로젝트 공통 규칙은 `AGENTS.md`, 어떻게
  일하는지는 스킬, 무엇이 틀렸고 어떻게 고쳤는지는 `notes.md`에 둔다. 같은 내용을 두 곳에 쓰지 않는다.

## 결과가 틀렸을 때

1. **멈춘다.** 틀린 결과를 대화에서 고쳐 넘어가지 않는다.
2. **층을 진단한다.** 절차에 단계·규칙이 없었나, 도구(참고 문서·스크립트)가 없거나 틀렸나, 완료 기준이 이 실수를
   잡지 못했나. 하나를 고른다. 첫 검증에서 완료 기준이 둘 넘게 실패했다면 결과가 아니라 절차를 의심한다.
3. **가장 작은 영구 수정을 고른다.** 한 층의 한 곳만 바꾼다. 같은 실수가 두 번째라면 명시적 규칙이나 완료 기준을
   더한다.
4. **초안을 보여 준다.** 바꿀 파일과 바뀌는 줄, 진단한 층과 근거를 보이고 승인을 받는다.
5. **적용하고 기록한다.** `notes.md` 맨 위에 날짜, 증상, 층, 수정, 확인 방법을 한 항목으로 쓴다.
6. **동기화하고 다시 돌린다.** `node scripts/sync-skills.mjs`로 `.claude/skills`에 반영한 뒤 같은 작업을 다시 해서
   고치기 전과 비교한다.

`notes.md` 항목 형식:

```markdown
## 2026-10-12 · 검증
- 증상: openapi.json만 바꾸고 생성 타입을 갱신하지 않았다
- 수정: 완료 기준에 "schema.d.ts가 같은 커밋에 있다"를 더했다
- 확인: 다시 돌려 기준이 누락을 잡는 것을 봤다
```

## 새 스킬을 만들 때

- 반복되는 작업 하나에 스킬 하나. 여러 작업을 한 스킬에 몰지 않는다.
- 이름은 소문자와 하이픈(`bit-backend`). 프론트매터에 `name`과 `description`만 둔다.
- 처음에는 사용자와 문답으로 실제 절차와 판단 기준을 끌어낸다. 기억으로 채우지 않는다.
- 만든 뒤 `node scripts/sync-skills.mjs`를 실행한다.

## 점검할 때

모든 스킬의 `notes.md`를 읽고 다음을 보고한다.

- 같은 층에 기록이 반복되는 스킬: 그 단계를 스크립트나 완료 기준으로 자동화할 후보
- 서로 겹치거나 비슷한 이름의 파일: 하나로 합칠 후보
- 쓰이지 않는 참고 문서: 지울 후보
- description이 실제 요청 문구와 어긋나 불리지 않았던 스킬

점검 결과도 고칠 것은 위 절차대로 초안을 보여 준 뒤 적용한다.

## 완료 기준

- 고친 스킬의 `notes.md` 맨 위에 이번 항목이 있다
- `node scripts/sync-skills.mjs`가 고친 스킬 이름을 출력한다
- 같은 작업을 다시 돌린 결과를 고치기 전과 비교해 보고했다
