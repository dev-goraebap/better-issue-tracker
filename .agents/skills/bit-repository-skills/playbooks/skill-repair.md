# 스킬 수선

BIT 저장소의 작업 방식은 이 스킬(`.agents/skills/bit-repository-skills/`)이 원본이다. 결과가 틀리면 대화에서 결과만
바로잡지 않고, 그 결과를 낸 플레이북을 고쳐 다음 작업이 처음부터 맞게 한다. 스킬은 앞으로의 작업 규칙이므로 수정은
초안을 보여 주고 승인을 받은 뒤 적용한다.

## 스킬의 구조

```text
.agents/skills/bit-repository-skills/
  SKILL.md       입구. 늘 지킬 것과 "작업 → 플레이북" 표만
  playbooks/     작업별 절차, 판단 규칙, 완료 기준
  references/    플레이북이 가리키는 세부 문서. 영역별 폴더(api, backend, frontend …)
  scripts/       기계적인 단계를 대신하는 스크립트
```

| 층 | 무엇 | 지킬 것 |
| --- | --- | --- |
| 입구 | `SKILL.md` | description은 실제로 할 요청 문구를 담고 1,024자를 넘지 않는다. 표의 각 행은 플레이북 하나를 가리킨다 |
| 절차 | `playbooks/` | 판단마다 근거 한 줄. 끝에 반증할 수 있는 완료 기준 |
| 도구 | `references/`, `scripts/` | 목적당 파일 하나. 파일 이름에 날짜·버전을 넣지 않는다. 비밀값과 일회성 결과물은 두지 않는다 |
| 검증 | 플레이북의 완료 기준, `scripts/check-bit-skill.mjs` | 반증할 수 있는 확인만 쓴다(실행할 명령, 같은 커밋에 있어야 할 파일). "깔끔하게" 같은 인상 표현은 기준이 아니다 |

- 예시가 필요하면 저장소의 실제 파일 경로를 가리킨다. 코드를 복사해 두면 코드가 바뀔 때 낡는다.
- 다른 플레이북이나 참고 파일은 링크로 가리킨다. "N절"처럼 번호로 가리키지 않는다. 번호는 고칠 때 밀린다.
- 제품·설계와 작업 규칙을 왜 그렇게 정했는지는 `docs/decisions.md`(D-023), 프로젝트 공통 규칙은 `AGENTS.md`, 어떻게
  일하는지는 이 스킬, 무엇이 틀렸고 어떻게 고쳤는지는 커밋 메시지와 BIT 업무에 둔다. 같은 내용을 두 곳에 쓰지 않는다.
- 수정 기록 파일(`notes.md`, CHANGELOG)은 두지 않는다. 지난 수정은 `git log -- .agents/skills/bit-repository-skills`로
  읽는다. 기록 파일은 읽히지 않은 채 쌓이고, 교훈은 플레이북이나 검사에 들어가야 다음 작업에 닿는다.

## 결과가 틀렸을 때

1. **멈춘다.** 틀린 결과를 대화에서 고쳐 넘어가지 않는다.
2. **층을 진단한다.** 입구가 엉뚱한 플레이북을 가리켰나, 절차에 단계·규칙이 없었나, 도구(참고 문서·스크립트)가 없거나
   틀렸나, 완료 기준이 이 실수를 잡지 못했나. 하나를 고른다. 첫 검증에서 완료 기준이 둘 넘게 실패했다면 결과가 아니라
   절차를 의심한다.
3. **가장 작은 영구 수정을 고른다.** 한 층의 한 곳만 바꾼다. 같은 실수가 두 번째이고 기계로 잡을 수 있으면
   `scripts/check-bit-skill.mjs`에 검사를 더한다. 그 검사는 CI에서 돈다.
4. **초안을 보여 준다.** 바꿀 파일과 바뀌는 줄, 진단한 층과 근거를 보이고 승인을 받는다.
5. **적용하고 남긴다.** 커밋 메시지에 증상, 층, 수정, 확인 방법을 쓰고, 작업 중인 BIT 업무에 같은 내용을 댓글로 남긴다.
6. **동기화하고 다시 돌린다.** `node scripts/sync-skills.mjs`로 `.claude/skills`에 반영한 뒤 같은 작업을 다시 해서
   고치기 전과 비교한다.

## 플레이북을 더할 때

- 반복되는 작업 하나에 플레이북 하나. 새 스킬을 만들지 않고 이 스킬의 `playbooks/`에 더한다.
- `SKILL.md` 표에 행을 더하고, description에 그 작업의 요청 문구를 더한다.
- 처음에는 사용자와 문답으로 실제 절차와 판단 기준을 끌어낸다. 기억으로 채우지 않는다.

## 점검할 때

`git log --format='%h %s' -- .agents/skills/bit-repository-skills`와 관련 BIT 업무를 읽고 다음을 보고한다.

- 같은 플레이북이 반복해 고쳐졌다: 그 단계를 스크립트나 검사로 자동화할 후보
- 서로 겹치거나 비슷한 이름의 파일: 하나로 합칠 후보
- 어느 플레이북도 가리키지 않는 참고 문서: 지울 후보(검사가 잡는다)
- 입구 표나 description이 실제 요청과 어긋나 엉뚱한 플레이북을 읽은 사례

점검 결과도 고칠 것은 위 절차대로 초안을 보여 준 뒤 적용한다.

## 완료 기준

- `node scripts/check-bit-skill.mjs`가 통과한다
- 커밋 메시지와 BIT 업무에 증상·수정·확인이 있다
- `node scripts/sync-skills.mjs`가 `bit-repository-skills`를 출력한다
- 같은 작업을 다시 돌린 결과를 고치기 전과 비교해 보고했다
