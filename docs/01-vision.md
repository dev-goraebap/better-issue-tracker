# 01. 비전과 범위

## 문제
현재 업무 환경에서 맥락이 세 곳에 흩어져 있다.

| 무엇 | 어디 | 역할 |
|---|---|---|
| 소스코드 | 로컬 git + 사내 GitLab | 코드가 **어떻게** 바뀌었나 |
| 이슈·회의록·작업항목 | Redmine | **왜** 바꾸나 (PM이 등록) |
| 산출문서 (docx, xlsx) | SharePoint / NAS | **근거** (요구사항서, 설계서 등) |

결과적으로
- 소스 변경의 이유가 산출문서에서 먼저 오는 경우가 많은데, 문서는 Git 밖에 있다.
- 문서가 왜 개정됐는지, 어느 버전이 어떤 코드의 기준이었는지 추적이 끊긴다.
- 로컬 에이전트에게 일을 시킬 때마다 사람이 이슈 복사, 문서 첨부, 관련 커밋 설명을 반복한다.

개인 프로젝트에서도 같은 문제가 있다. 혼자 에이전트와 작업하면 회의록 없이
결정이 에이전트 세션 안에서 일어나고, 세션이 끝나면 사라진다.

## 제품 분류
**ALM (Application Lifecycle Management)** 에 가장 가깝다.
요구사항·변경·문서·이슈·코드 사이의 추적성(traceability)을 관리하는 영역
(예: Azure DevOps, Polarion, codeBeamer, Jama).

| | 기존 ALM | BIT |
|---|---|---|
| 무게 | 무겁고 비쌈, 규제 대응 중심 | 가볍고 셀프호스팅 |
| 기록 주체 | 사람이 꼼꼼히 입력 | 에이전트가 대부분 기록 |
| 기록의 용도 | 감사·증빙 | 증빙 + **에이전트의 맥락** |

한 줄 정의: **AI 네이티브 경량 ALM** — "사람과 에이전트가 남긴 결정·산출물·코드를 잇는 추적 플랫폼"

주변 분류와의 관계
- 이슈 관리(Kaneo, Linear, Jira): 작업항목만 있음. "왜"와 산출물이 없음.
- DMS(SharePoint): 파일과 버전은 있지만 작업·코드와 연결이 없음.
- ADR 도구: 결정은 남기지만 실행 흐름과 떨어져 있음.
- AI 컨텍스트 계층(MCP, 에이전트 메모리): 출발 동기는 여기.

AI-DLC(AWS의 AI-Driven Development Lifecycle: Inception → Construction → Operations)와 방향이 겹친다.
AI-DLC는 방법론이고 "결정과 산출물이 사는 집"은 정하지 않는다.
BIT는 그 기록 시스템(system of record)이 될 수 있다. 단, 이름에 AIDLC를 넣지는 않는다.

## 차별점
기능 각각(이슈, 문서, Git)은 이미 좋은 도구가 많다. 이길 수 있는 곳은 **연결**이다.
회의/세션에서 결정 → 작업항목 → 문서 개정 → 코드 변경이 **하나의 그래프로 이어지는 것**.

## 사용 맥락
1. **개인 프로젝트** (1차 목표): 사용자 본인 + 로컬 에이전트.
2. **회사 연동** (나중): 사용자가 만든 사내 오피스 플랫폼(연차·일정·회의록 운영 중, Redmine 이전 합의됨)과
   연동하는 것에 대해 회사 허락을 받았다. 연동 설계는 나중에 다룬다.

## 범위
### 1차 (MVP)
- 프로젝트, 작업항목 (Kaneo 베이스)
- 결정 (Decision)
- 세션·회의 기록 (Session)
- 워크스페이스 문서함 (폴더 + 프로젝트 라벨) — 1차는 일반 파일만 (D-019)
- 업로드 파일의 텍스트 자동 변환
- Git 저장소 Markdown을 정본으로 참조하는 산출물 + PDF 생성 (D-016)
- 엔티티 간 링크, 연결 타임라인
- Git 웹훅 연동 (커밋/MR ↔ 작업항목)
- REST API + MCP 서버

### 이후
- 관리 문서: 버전·개정 사유·변경 요약·버전 비교·개정이력표, 개인 모드 변경 통제 (D-019)
- 폴더 감시(NAS/로컬) → 반영 대기함
- 팀 모드 (편집 잠금, 검토자 승인)
- 릴리스 기준선(baseline) 스냅샷과 산출물 묶음 내보내기
- Markdown 산출물의 docx 내보내기
- 근거 문서 개정 시 영향 알림
- 사내 플랫폼 연동
- 프로젝트별 문서함 (워크스페이스 문서함 하나로 부족해지면 — D-015)

### 범위 밖
- Git hosting 자체 구현
- 문서 편집기 (원본은 Word/Excel에서 편집 후 업로드)
- 결재 워크플로, 위키
- 진짜 일정(반복·참석자·회의실·알림). 본체의 캘린더는 날짜 있는 이슈만 보인다. 호호 HR의 결재·휴가·일정은 비공개 오피스 확장이 맡는다 (D-071)
