# 04. 산출물 등록과 변경 통제

> **대체됨 (2026-10-26, D-093·D-094)**: 문서함은 업로드 파일·Git md를 산출물로 두는 모델에서, 프로젝트마다 폴더에 두는 마크다운 문서로 바뀌었다. 파일은 문서에 첨부한다. 아래는 예전 설계이고, 관리 문서(버전·확정)나 폴더의 외부 항목 연결을 다시 다룰 때 참고한다.

## 일반 파일과 관리 문서 (D-018, D-019)
문서함의 파일은 두 종류다. **문서마다 정하고, 기본은 일반 파일.** **1차에는 일반 파일만 만든다.**

| | 일반 파일 (1차) | 관리 문서 (이후) |
|---|---|---|
| 다시 올리면 | 그냥 덮어씀 | 초안을 덮어쓰고, 확정하면 새 버전 |
| 문서 ID (REQ-001) | 없음 | 관리 문서로 전환할 때 부여 |
| 개정 사유·변경 요약 | 없음 | 확정할 때 필수 |
| 이슈·결정과 링크 | 됨 (산출물을 가리킴) | 됨 (특정 버전 + 위치 메모를 가리킴) |
| 버전 비교·개정이력표·영향 알림·기준선 | 없음 | 있음 |

- 일반 파일은 언제든 관리 문서로 바꿀 수 있다. 바꾸는 순간의 파일이 v1.0이 된다.
- 1차 기간에 덮어쓴 업로드 파일의 예전 내용은 남지 않는다. Git 정본은 이력을 Git이 남긴다.
- 나중에 붙이기 쉽도록 1차부터 스키마는 산출물/버전을 나눠 두고(산출물당 버전 1행), 링크에 버전·위치 칸을 비워 둔다 (`02-domain-model.md`).

아래 "버전 상태"부터 "프로젝트별 통제 모드"까지는 **관리 문서(이후)** 의 설계다.

## 정본과 파생본 (D-016)
산출물마다 **정본은 하나**다. 나머지는 플랫폼이 정본에서 만드는 **파생본**이고, 사람이 고치지 않으며 언제든 다시 만들 수 있다.

| 정본 종류 | 정본이 있는 곳 | 파생본 | 화면 버튼 |
|---|---|---|---|
| 업로드 파일 (docx·xlsx·pptx·PDF) | 플랫폼 저장소 | 텍스트 (업로드 후 자동 변환) | 원본 받기 · 텍스트 보기 |
| 플랫폼 Markdown | 플랫폼 저장소 | PDF (요청할 때) | 읽기 · PDF 받기 |
| Git 저장소 Markdown | Git 저장소 (경로 + 커밋) — 복사하지 않음 | PDF (요청할 때) | 읽기 · PDF 받기 · 저장소 열기 |
| 그 밖의 파일 (이미지·zip·도면 등) | 플랫폼 저장소 | 없음 (설명 칸만) | 원본 받기 |

- **자동 변환**: 업로드가 끝나면 백그라운드에서 변환한다(트랜잭션 밖). 상태는 변환 중 / 완료 / 실패.
  실패해도 등록은 유효하고, 그 버전만 검색·diff·에이전트 읽기가 안 된다. 변환 도구가 지원하는 형식만 변환한다.
- **Git 정본**: 개발 환경에 이미 md가 있는 문서(아키텍처 구성도, 에이전트 스킬, 형상관리 문서 등). 플랫폼은 참조만 한다(D-003).
  일반 파일이면 추적하는 브랜치의 최신 커밋을 보여 준다. 관리 문서가 되면 초안 = 최신 커밋, 확정 = 특정 커밋 또는 태그에 고정. 제출용은 PDF로 받는다.
- **화면**: 목록에는 산출물 한 줄. 정본 종류는 배지(docx / md / Git)로 구분하고, 파생본은 버튼으로만 노출한다.

## 등록 경로
| 경로 | 설명 |
|---|---|
| 웹 업로드 | docx·xlsx 등 드래그 앤 드롭. 기본. |
| 에이전트(MCP) | 새 Markdown 문서 작성, 또는 기존 문서 갱신(관리 문서면 초안으로). 개인 프로젝트의 주 경로. |
| Git 저장소 연결 | 저장소 경로(파일 또는 폴더)를 산출물로 등록. 내용은 복사하지 않고 커밋을 참조. |
| 폴더 감시 (선택, 이후) | NAS/로컬 폴더 변경 감지 → **바로 버전으로 만들지 않고 "반영 대기함"** → 사람이 확인 후 버전으로 올림. 기존 습관(NAS 저장)을 바꾸지 않고 끌어오는 다리. |

등록 시 공통 처리
1. 정본 저장 (업로드 파일은 그대로, Git 정본은 경로 + 커밋만)
2. 업로드 파일이면 텍스트 변환 (docx → Markdown, xlsx → 시트별 CSV/Markdown) — 검색·diff·에이전트용
3. 문서함의 폴더에 놓음. 문서 ID(워크스페이스 안에서 고유)는 관리 문서로 전환할 때 부여

새로 쓰는 문서는 처음부터 Markdown으로 만든다. 작성은 에이전트(MCP)나 외부 편집기에서 하고 플랫폼에는 등록만 한다.
플랫폼은 문서 편집기를 제공하지 않는다(범위 밖). Markdown → docx 내보내기는 이후 범위.

## 버전 상태 (관리 문서, 이후)
```
초안(draft) ──검토──▶ 확정(released) ──▶ 대체됨(superseded)
 자유롭게 수정          수정 불가, 새 버전만      다음 버전이 확정되면
```

- **초안은 산출물당 한 칸** (D-013). 다시 올리면 그 초안을 덮어쓴다. 초안끼리의 중간 이력은 남기지 않는다.
- **버전 번호는 확정할 때 붙는다.** 기본은 작은 개정(v1.0 → v1.1), 확정하는 사람이 큰 개정(→ v2.0)을 고를 수 있다.
  확정본 번호에는 구멍이 생기지 않는다.
- diff는 "직전 확정본 ↔ 현재 초안"으로 본다.

## 통제 규칙 (관리 문서, 이후)
바이너리 문서는 병합이 안 되므로 핵심은
**동시에 고치지 못하게, 이유 없이 바뀌지 못하게, 확정본은 못 건드리게.**

- **편집 잠금(체크아웃)**: 편집 중이면 다른 사람은 새 버전 업로드 불가. (팀 모드)
- **개정 사유 필수**: 확정 문서의 새 버전은 이슈 또는 결정 링크 필수.
  없으면 그 자리에서 이슈 생성을 유도. 초안 단계 수정은 사유 없이 자유.
- **확정본 불변**: 덮어쓰기 금지. 변경은 항상 새 버전.
- **diff 기반 검토**: 확정 전 이전 확정본과의 텍스트 diff 확인. 개인=본인 확인, 팀=검토자 승인.
- **변경 요약 필수**: 확정할 때 한두 줄로 무엇이 바뀌었는지 적는다(에이전트가 올리면 에이전트가 쓴다).
  docx·xlsx의 diff는 변환 텍스트 기준이라 참고용이고, 변경 요약이 믿을 만한 기록이다. md 정본의 diff는 정확하다.
- 개정 사유와 변경 요약이 쌓이면 문서의 **개정이력표가 자동 생성**된다.
- **추적 단위**: 이슈·결정의 링크는 특정 버전을 가리키고, 필요하면 "3.2항", "요구사항 시트 12행" 같은 위치 메모를 붙인다.
  문서 안 항목 단위 추적은 하지 않는다(docx·xlsx 변환으로는 항목을 안정적으로 나눌 수 없음). 영향 알림은 문서 단위로 간다.
