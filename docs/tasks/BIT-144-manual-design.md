# 프로젝트 매뉴얼 설계

BIT-144. 설계 검토용 구현이며 서버 저장 기능의 완료를 뜻하지 않는다.

## 확정된 요구

매뉴얼은 제품·프로그램·업무를 올바르게 다루는 방법과 절차를 체계적으로 설명하는 독립 도메인이다. 사용자 매뉴얼, 개발 지침, 아키텍처와 코드 스타일을 담는다. 프로젝트마다 필요할 때 여러 개 만든다. 기존 파일함과 HTML 페이지, 업무 설명은 유지한다. 회의록 연결이나 기존 문서의 자동 편입은 하지 않는다.

목록은 이름·설명·기본 SVG 표지 또는 사용자 이미지를 가진 카드다. 내부는 콘텐츠 왼쪽 탐색 메뉴, Markdown 본문, 현재 페이지 목차를 공통으로 제공한다. 검색·이전/다음·페이지 복사·Markdown/PDF 내보내기와 페이지별 개선 댓글을 제공한다. 매뉴얼의 본문 품질을 검증한 뒤 업무 설명의 공통 뷰어/에디터로 확장한다.

## 도메인과 불변 조건

- Manual: workspaceId, projectId, id, title, description, coverPreset, coverFileId?, version, 작성/수정 actor/time. 프로젝트 권한을 상속한다.
- ManualSection: id, manualId, title, position. 1차는 한 단계 섹션이며 페이지는 섹션에 속하거나 최상위에 둘 수 있다. 깊은 중첩은 사용자 검토 후 판단한다.
- ManualPage: id, manualId, sectionId?, title, body(Markdown), position, version, 수정 actor/time. 페이지 ID는 제목/위치 변경과 무관하게 유지한다.
- ManualComment: id, pageId, body, author/agent, resolvedAt/by?, version. 해결 후에도 기록이 남으며 재열 수 있다. 구절 댓글은 후속 범위다.
- 순서 변경은 동일 매뉴얼의 ID를 한 번씩 포함해야 한다. 다른 매뉴얼의 섹션으로 페이지를 옮길 수 없다.
- 파일은 매뉴얼 소유 첨부로 처리한다. 파일함이나 업무 첨부의 접근 권한을 우회하지 않는다.
- 서버 수정은 expectedVersion으로 충돌을 검사한다. 실패/충돌 시 클라이언트 초안을 보존한다.

## 화면과 상호작용

1. 목록: 프로젝트 맥락, 검색, 만들기. 기본 표지는 책/구조/경로 SVG이며 이미지 없는 카드도 완성된 모습이다.
2. 읽기: 탐색 기본 232px, 200~360px 범위에서 화면 여유에 따라 너비 조절. 본문 최대 720px, 목차 160px. 본문 16px/1.85, h2 25px, 단락 1em, 섹션 2em. Pretendard·Astryx 테마 토큰 사용. 긴 표/코드는 해당 영역에서 가로 스크롤.
3. 제목과 도구를 상단에 두고 제작 날짜·사진 장수·홍보 문구는 넣지 않는다. 댓글은 필요할 때 연다.
4. 편집: 제목/섹션/본문 초안을 명시적으로 저장/취소한다. 같은 Markdown 스키마와 본문 폭을 사용하며 소스 편집도 제공한다.
5. 구성: 섹션/페이지 생성, 섹션 간 이동, 위·아래 이동 버튼. 드래그에만 의존하지 않는다.
6. 모바일: 탐색/목차는 별도 버튼으로 펼치고 본문을 좁은 3열로 유지하지 않는다.
7. 링크 복사와 `Markdown 복사`를 구분한다. Markdown 내보내기는 현재 페이지, PDF는 현재 페이지/전체 매뉴얼을 선택한다. 인쇄에 탐색/도구/댓글은 제외한다.
8. 현재 선택을 URL에 남긴다. 미저장 편집 중 이동은 명시적으로 폐기/계속 편집하게 한다. 이미지 원본 확대와 제목 앵커를 제공한다.

## API/MCP 계약 초안 — 미구현

REST `/api/v1/workspaces/{workspaceId}/projects/{projectId}/manuals`: 목록/생성. `/{manualId}`: 조회/수정/소프트 삭제. 하위 `/sections`, `/pages`, `/order`: 구성/순서. `/pages/{pageId}/comments`: 댓글. 댓글 `/resolution`: 해결/재열기. 페이지 GET/PATCH에 body/version을 주고받고 목록은 본문을 제외한다. 본문 검색은 매뉴얼 범위 서버 검색으로 제공한다.

서비스에서 접근/수정 권한·소속·버전을 검사한다. Manual용 권한의 세부 표는 구현 단계에서 확정하며 미리보기는 권한 검증을 대신하지 않는다.

MCP list/get/create/update_manual, get/create/update_manual_page, reorder_manual, add/resolve_manual_comment를 같은 서비스 위에 둔다. 섹션 생성/수정/페이지 이동도 명시적 계약으로 제공한다. 삭제 도구는 1차 범위 밖이다. Markdown 내보내기는 그림이 없으면 .md, 있으면 .md와 원본 그림을 상대 경로로 연결한 ZIP을 제공한다. 서버 구현에서도 소유 첨부와 원본 바이트를 검사한다.

## 이번 로컬 검토 범위

개발 모드에서만 열리는 매뉴얼 미리보기다. 예제 매뉴얼과 빈 상태를 보고 생성·읽기·편집·구성·댓글/해결·검색·내보내기를 브라우저 저장소에서 조작한다. workspace/project별 저장이다. 사용자 요청에 따라 상시 미리보기 안내 띠는 제거하고 저장 범위는 검토 문서와 전달 내용에서 설명한다. 서버 저장처럼 알리지 않는다.

검토 후 서버 모듈/Flyway/API/MCP와 권한·충돌을 구현한다. 공개 배포·승인·제품 버전별 매뉴얼·다국어·구절 댓글·파일함 재구성은 이번에 추가하지 않는다.

## 검토 기준

- 목록 → 생성 → 페이지 작성 → 읽기 → 댓글/해결 → 재진입을 끝까지 검토한다.
- Markdown 내용/선택 페이지, PDF 선택 범위를 검증한다. 실제 PDF 페이지 분할은 브라우저 인쇄 검증이 필요하다.
- 1440/390px, 라이트/다크, 긴 제목·표·코드·빈 페이지에서 확인한다.
- 화면 정보가 과하거나 본문 폭이 부족하면 밀도와 도구 배치를 재검토한다. 검증/피드백은 BIT-144에 남긴다.

## 로컬 확인 결과

2026-10-31: 독립 대조 후 PDF에서 확대 버튼 안 이미지가 숨는 문제, 편집 중 페이지 추가가 초안을 잃는 문제, 첫 페이지 링크가 순서 변경에 영향을 받는 문제를 수정했다. 생성 → 페이지 작성/저장 → 섹션 추가/이동 → 댓글/해결 → 새로고침 보존을 실제 조작했다. 미저장 이탈 취소 후 제목 초안도 보존된다. 390px 프레임에서 문서 폭 390px, 스크롤 폭 390px이며 그림 원본이 로드된다. 기본/다크 테마와 넓은 화면에서 본문/탐색/목차를 확인했다.

클라이언트 check는 58개 테스트와 규칙 검사·타입·빌드를 통과했다. Markdown ZIP을 실제로 내려받아 Python zipfile로 CRC/UTF-8 파일명/상대경로/그림 원본 바이트를 대조했다. PDF 인쇄 문서는 구현했으나 앱 내 브라우저에서 OS 인쇄 대화상자와 최종 PDF 페이지 나눔을 확인하지 못했다. 서버/API/MCP 저장·권한과 다중 사용자 충돌은 미구현이며 이번 로컬 미리보기로 검증했다고 보지 않는다.

### 사용자 화면 검토 반영

상시 안내 띠와 MANUALS 표기를 제거했다. 생성 버튼은 공통 상단 헤더의 강조 생성 스타일로, 목록/내용 검색은 기존 SearchToggle로 옮겼다. 매뉴얼명과 현재 섹션을 상단 경로에 표시하고 본문 도구도 같은 헤더 우측에 모아 중복 도구 행을 제거했다. 내부 탐색은 드래그/방향키/너비 설정으로 조절하며 브라우저에 기억한다. 모바일은 BIT의 64rem 기준으로 전환한다. 상한 360px, 방향키 조절, 새로고침 후 344px 보존, 기본 232px 복원, 목록/내용 검색과 결과 이동, 390px 헤더 영역/가로 넘침을 확인했다. 클라이언트 check(58개)와 diff 검사를 통과했다.

추가 검토에서 별도의 너비 버튼/설정창을 제거했다. 경계선 드래그·방향키·두 번 눌러 기본 너비 복원은 유지한다. Markdown 복사와 현재 페이지 목차는 페이지 도구 메뉴로 옮기고 댓글 아이콘의 테두리는 제거했다. 탐색 메뉴의 첫 섹션 위 중복 여백을 없애고, 항목 최소 높이 32px·항목 사이 2px·섹션 사이 20px로 정리했다.
