# T-006. 데모 화면을 실제 앱으로 옮기고 서버에 연결 (작업 지시서)

> 작성: 2026-10-24. 선행: T-004 서버 `33c26f8`·화면 `17ccc6f`, T-005 기반 구현, 데모 D-065~D-070 `dd6c21d`, D-071 `ed96a6d`.
> 상태: 1·2·3단계 완료. 4단계(나머지 화면)·5단계(뷰 저장) 남음. 사용자가 HR(오피스 확장, D-071) 전에 데모를 실제 앱으로 제대로 옮겨 기능을 연결하기로 했다.
> bit-architecture / bit-backend / bit-database / bit-api-contract / bit-frontend를 적용한다.

## 목표와 범위

`/demo`에서 다듬은 화면(D-065~D-070)을 `/w/...` 실제 주소의 화면으로 만들고, 목 데이터 대신 서버를 읽고 쓴다. 다 옮기면 실제 앱이 데모와 같은 모양으로 동작하고, 같은 이미지로 배포해 쓸 수 있다.

포함:
- 셸: 워크스페이스 전환·알림 벨·프로젝트 목록·범위 콤보박스·설정 메뉴 전환·계정 카드(데모 셸)를 실제 세션·워크스페이스·프로젝트로.
- 이슈: 홈(전체)과 프로젝트의 이슈 화면, 여섯 레이아웃(리스트·캘린더·칸반·타임라인·카드·히스토리), 필터·표시 메뉴, 상세 모달·페이지, 새 이슈 모달·페이지, 편집.
- 라벨: 워크스페이스 라벨과 이슈 연결(서버 새로), 결정기록 시스템 라벨.
- 전체 이슈 조회(서버 새로)와 칸반의 상태 분류.
- 뷰: 공유·나만 보기·사람별 조정(D-068)을 서버에 저장.
- 구성원·초대, 워크스페이스 설정, 프로젝트 설정(컬럼), 계정 설정(비밀번호·API 키·화면)을 데모 모양으로.

제외:
- 받은함 알림 생성·읽음(알림 API가 없다). 벨과 받은함 화면은 빈 상태로 둔다.
- 문서함(산출물), 댓글·활동 타임라인, 결정 REST·화면. T-005의 남은 단계가 맡는다. 결정기록 라벨 이슈의 결정 상태 칸은 T-005의 결정과 합칠 때 정한다.
- 프로필 이름·사진 변경(서버 API 없음, 읽기만), 워크스페이스 로고(D-071), HR 오피스 확장.
- 진짜 일정(반복·참석자, D-071). 데모의 '일정' 라벨과 시각·종일·참석자가 붙은 샘플은 옮기지 않는다.

## 확정한 권장 정책

| 항목 | 적용 정책 | 이유·기각 대안 |
|---|---|---|
| 옮기는 방식 | 데모의 페이지·위젯을 실제 FSD 자리로 옮기고 목 저장소를 TanStack Query로 바꾼다. 같은 일을 하던 옛 실제 화면(WorkItemsPage·WorkBoard·HomePage·MyTasks 등)은 지운다 | 옛 화면에 데모 모양을 덧칠하기는 두 구조가 섞여 기각 |
| 데모 경로 | 옮긴 화면의 데모 경로는 지운다. 목 데이터가 필요 없는 UI 패턴(상태·다이얼로그)만 `/demo/patterns`에 남긴다 | 데모와 실제 화면 두 벌 유지는 고칠 때마다 두 번이라 기각 |
| 상태 | 상태는 지금처럼 `board_column_id`. NULL이 '상태 없음'(D-066)이다 | 이미 서버 계약과 일치 |
| 상태 분류 | `board_column`에 `category`(todo·doing·done)를 둔다. 기존 행은 final→done, 맨 앞 컬럼→todo, 나머지→doing으로 채운다. 전체의 칸반은 분류로 묶는다 | 프로젝트마다 컬럼이 달라 전체에서 묶을 기준이 필요(D-066 권장안 확정). 이름으로 추측하기는 기각 |
| 라벨 | 06-schema의 `label`·`work_item_label`. 워크스페이스에 한 벌. 결정기록은 `is_system` 라벨로 워크스페이스 생성 때 만들고 이름 변경·삭제를 막는다. 이슈 만들기·수정에서 `labelIds`를 받는다 | 작업마다 사본 행(Kaneo)은 D-009로 기각 |
| 전체 조회 | `GET /workspaces/{id}/work-items`. 필터: projectIds, labelIds, columnIds·category, assigneeId, priority, 날짜 범위, hasDates, q. 정렬·커서는 프로젝트 목록과 같다 | 프로젝트마다 따로 불러 화면에서 합치기는 페이지와 정렬이 깨져 기각 |
| 뷰 | `issue_view`(워크스페이스, 소유자 NULL=공유·값=나만 보기, 이름·아이콘·색·레이아웃·필터·정렬·컬럼 JSON)와 `issue_view_tweak`(뷰, 사용자, JSON). 기본 뷰 '전체 이슈'는 고정 | 데모의 localStorage는 사람·기기마다 달라 공유가 안 돼 기각 |
| 뷰 권한 | 공유 뷰는 owner/admin과 만든 사람이 고치고 지운다. 나만 보기는 소유자만. 조정은 각자. '모두의 기본값으로 저장'은 고칠 수 있는 사람만 | D-068 그대로 |
| 마스크 라우트 | 상세·새 이슈는 D-069·D-070 그대로 실제 주소에서 모달로 열리고 새로 고침하면 페이지다 | 데모에서 검증한 방식 |
| 날짜 | 이슈는 시작일·마감일(LocalDate)만. 캘린더·타임라인은 날짜 있는 이슈만 보인다 | D-071 |

## 단계와 커밋

각 단계는 스스로 검사를 통과하고 커밋한다.

1. **서버 기반**: V5에 label·work_item_label과 board_column.category. 라벨 CRUD, 이슈 만들기·수정의 labelIds, 응답의 labels·category, 전체 이슈 조회. 서버 테스트.
2. **셸**: DemoLayout을 실제 WorkspaceLayout으로 옮긴다. 세션의 사람, 워크스페이스 전환, 프로젝트 목록과 만들기, 범위 콤보박스, 설정 메뉴 전환(워크스페이스·프로젝트·계정), 벨(빈 받은함).
3. **이슈 화면**: 홈·프로젝트 이슈 화면과 여섯 레이아웃, 필터·표시, 상세·새 이슈·편집을 서버에 연결. 이 단계의 뷰는 데모처럼 브라우저 저장소에 둔다.
4. **나머지 화면**: 구성원·초대, 워크스페이스 설정, 프로젝트 설정(컬럼·분류), 계정 설정. 옛 화면과 옮긴 데모 경로를 지운다.
5. **뷰 저장**: V6 issue_view·issue_view_tweak와 REST, 화면의 저장소를 서버로 바꾼다.

## 반증 가능한 완료 기준

- 새 볼륨의 이미지에서 첫 관리자→워크스페이스→프로젝트→이슈 만들기(라벨·상태 없음 포함)→칸반 이동→상세 수정→보관까지 실제 화면으로 된다.
- 홈(전체)에 여러 프로젝트의 이슈가 한 목록·칸반(분류별)·캘린더에 보인다.
- 뷰를 만들면 다른 구성원에게도 보이고, 나만 보기는 본인에게만, 조정은 본인에게만 남는다(5단계).
- 상세·새 이슈 모달의 주소창은 그 주소이고, 새로 고침하면 페이지다.
- `npm run check --prefix client`, 서버 `./gradlew check`, 도커 이미지 빌드·healthy가 통과한다. 1440px·390px 화면을 확인한다.

## 진행 기록

### 2026-10-25 1단계 서버 기반 (`abc3729`)

- **스키마**: V5에 `label`·`work_item_label`과 `board_column.category`를 더했다(06-schema의 T-006 V5 계약). 기존 행 분류와 워크스페이스별 결정기록 라벨은 V5가 채운다.
- **라벨 모듈**: `module/label`을 새로 두고 `LabelFacade`(배치 조회·접근 검사)를 공개한다. 의존은 label → workspace, workitem → label이며 순환이 없다. 새 워크스페이스의 결정기록 라벨은 workspace가 발행하는 `WorkspaceCreatedEvent`를 label이 `BEFORE_COMMIT` 리스너(`Propagation.MANDATORY`)로 받아 같은 트랜잭션에서 만든다. 기존 `TargetChangedEvent`→활동 기록과 같은 방식이다. workspace가 LabelFacade를 부르면 label → workspace와 순환이 생기고, Spi는 구현이 하나뿐인 확장점이라 이벤트를 골랐다.
- **라벨 REST**: `GET/POST /workspaces/{id}/labels`, `GET/PATCH/DELETE /labels/{labelId}`. 쓰기는 owner/admin/member, viewer는 읽기만, 비구성원은 404. 수정·삭제는 다른 업무처럼 `expectedVersion`(삭제는 쿼리)을 받는다. 시스템 라벨은 이름 변경·삭제가 `LABEL_SYSTEM_LOCKED`(409)이고 색은 바꿀 수 있다. 같은 이름은 `LABEL_NAME_CONFLICT`(409).
- **이슈**: 만들기는 `labelIds`(생략·null=없음), PATCH는 `labelIds` 생략=유지, 값=전체 교체, `[]`·null=비움. 라벨은 작업항목 애그리거트의 일부라 내용과 함께 바뀌면 version이 한 번 오른다. 지운 라벨·다른 공간 라벨은 `WORKITEM_LABEL_INVALID`(400). 응답에 `labels`(시스템 먼저, 이름순, 지운 라벨 제외)와 `columnCategory`(백로그는 null)를 더했다. 라벨 표시는 페이지를 정한 뒤 LabelFacade 배치 조회 한 번, 분류는 분류 필터 때문에 이미 붙인 board_column(기본 키 to-one)에서 같은 쿼리로 읽는다.
- **목록**: 프로젝트 목록·내 작업에 `labelId`(여럿, 어느 하나), `category`(todo·doing·done·none, 여럿), `hasDates`를 더했다. 새 `GET /workspaces/{id}/work-items`는 같은 응답·커서·정렬에 `projectId`·`columnId`(여럿)를 더 받는다. 보관·삭제된 프로젝트의 이슈는 내 작업처럼 늘 뺀다. `from`/`to`는 두 목록 모두 마감일 범위가 아니라 시작~마감 기간 겹침(하나만 있으면 그날)으로 바꿨다(D-072).
- **컬럼**: 응답에 `category`, 만들기·수정에 `category`를 받는다. 완료 컬럼에 done이 아닌 분류를 보내면 `PROJECT_COLUMN_CATEGORY_INVALID`(400)로 거절한다. 생략하면 만들 때는 완료 done·나머지 doing, 고칠 때는 유지하되 완료가 되면 done, 완료에서 풀리면 doing이다.
- **보안 경로**: 새 경로를 Spring Security 허용 목록과 API 키 업무 경로에 더했다(라벨 읽기·쓰기, 전체 이슈 읽기).
- **검사**: 서버 `./gradlew.bat check` 통과(단위 28, 통합 86 — 새 라벨 통합 5·V4→V5 마이그레이션 1 포함). OpenAPI와 `schema.d.ts`를 다시 만들었고 `npm run check --prefix client` 통과. MCP 도구는 아직 없어 바뀐 것이 없다.

### 2026-10-25 3단계 이슈 화면

- 홈(전체)과 프로젝트가 `IssuesPage` 하나다. 범위의 살아 있는 이슈를 100개씩 이어 받아(최대 2,000개, 넘으면 `isCapped`) 화면에서 필터·정렬·묶음을 한다. 서버 정렬이 `createdAt`·`position`뿐이라, 데모의 수정일·우선순위·제목 정렬을 지키려고 고른 방식이다. 그보다 커지면 서버 정렬·필터로 바꾼다.
- 뷰 필터는 범위와 상관없이 같은 뜻이 되도록 상태를 분류(todo·doing·done·none)로, 라벨을 id(결정기록은 `system`)로 저장한다. 뷰는 5단계 전까지 이 브라우저(`bit-views`)에 둔다. 시작 뷰: 전체 이슈, 백로그(상태 없음), 진행 보드, 캘린더, 결정기록(히스토리).
- 칸반: 프로젝트에서는 컬럼별 칸이고 카드를 끌어 다른 칸 끝으로 옮긴다(move API). 전체에서는 분류별 칸이고 끌기는 없다(어느 프로젝트 컬럼으로 갈지 정할 수 없어서).
- 캘린더: 이슈에 시각이 없으므로(D-071) 월 보기만 두고 주·업무 주와 시간 격자는 뺐다. 막대는 시작~마감, 끌면 두 날짜가 같이 옮겨진다. '+N개 더'는 그날 이슈 목록을 연다. 공휴일 표시는 자료가 없어 뺐다.
- 상세(모달·페이지): 속성 패널의 상태·우선순위·담당자·시작일·기한·라벨이 각각 바로 저장되는 알약이다. 편집(제목·설명)은 `/edit` 페이지, 더보기에 링크 복사·보관·삭제. 연결·활동·댓글은 T-005 뒤로 미뤘다.
- 새 이슈(모달·페이지): 프로젝트·상태(그 프로젝트 컬럼 또는 상태 없음)·우선순위·담당자·라벨·기한, 칸반 +는 그 칸(전체에서는 그 분류의 첫 컬럼)에서 시작한다.
- 옛 화면(프로젝트 작업 화면·상세·홈·내 작업)과 그 기능들(작업 필터·이동·양식)을 지웠다. `/my-tasks`는 홈으로 넘긴다(내 작업은 담당자 필터 뷰로 만든다).
- 기한 고르기는 상세와 새 이슈가 함께 쓰도록 `shared/ui/due-picker`로 옮기고 오늘을 실제 날짜로 바꿨다.
- 확인: 새 jar로 V3→V5 마이그레이션 뒤 테스트 서버에서 전체 리스트·칸반(분류)·캘린더, 상세 모달에서 우선순위 저장(version 1), C 키 새 이슈 만들기와 토스트, 프로젝트 칸반 끌기(할 일→검토 중) 저장을 확인했다. `npm run check` 통과.
