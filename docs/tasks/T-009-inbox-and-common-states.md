# 알림함과 공통 상태 화면 정리

업무 BIT-60(공통 상태·아이콘·사이드바), BIT-61(알림함). 사용자의 추가 요청을 PR #54와 0.10.0 배포에 함께 반영한다.

## 확정한 요구

- 만들기·생성 버튼은 더 작은 모서리. 공통 생성 클래스에서 4px로 정하고 각 생성 폼에도 같은 의미를 부여한다.
- 접힌 사이드바 알림은 다른 내비게이션 아이콘과 같은 16px, 설정은 같은 중심선. 알림/기본 메뉴/프로젝트는 간격 대신 구분선으로 나눈다.
- 알림함은 데스크톱 좌측 목록·우측 선택 상세. 우측에는 알림 내용과 해당 콘텐츠 이동 링크만 두고 전체 업무 상세를 넣지 않는다. 좌측 목록은 포인터·키보드로 너비를 조절하며 구분선은 전체 높이로 잇는다. 읽음 처리와 목록 위치를 유지한다. 모바일은 선택한 상세와 목록을 오간다. 선택은 URL에 보존한다.
- 공통 빈 상태·오류는 컨테이너의 남은 공간에서 중앙보다 조금 위에 한 그룹으로 놓는다. 그림 프레임은 320×176px이며 좁으면 너비만 제한한다. 그림과 문구는 함께 등장하고 동작 줄이기를 유지한다.
- 작은 로켓은 결과가 들어갈 공간의 정중앙. 로켓 재생은 1.2배, 로딩 종료 페이드는 400ms, 그림 페이드는 600ms로 줄인다.
- NavIcon은 텍스트 크기를 따르는 기본값과 navigation/standalone 역할을 구분한다. 개별 화면마다 20px를 보정하는 방식을 줄인다.

## 구현과 검증

StateRegion과 useFillRoom으로 상태·로딩의 공간을 공유한다. 알림 상세는 수신자 권한을 검사하는 단건 조회 API로 읽으며 원본 업무로 이동하는 링크를 둔다. 알림 선택·읽음·필터·새로고침·목록 복귀, 빈 상태·오류·로딩, 접힌 사이드바와 모바일 화면을 실제 렌더링으로 확인한다.


## 알림 표현과 추가 피드백

- 발신자는 사용자 프로필 이미지·이름으로, 자동 알림은 시스템 아바타로 표시한다. 에이전트가 대행한 경우 별도 이름 배지를 붙인다. 목록과 단건 API에서 같은 발신자 계약을 사용한다.
- 읽지 않은 항목은 점 대신 포인트 색상 5% 배경과 굵은 제목으로 구분한다. hover는 8%, 선택은 9% 배경과 왼쪽 선을 사용한다. 읽음 처리 후 unread 배경은 해제된다.
- 단독 오류 화면은 스크롤 조상이 없어도 뷰포트의 남은 높이를 사용한다. display: contents 래퍼와 레이아웃에 참여하지 않는 script/style은 높이 계산을 끊지 않는다. 아래에 실제 콘텐츠가 있으면 그 공간을 차지하지 않는다.
- 로컬에만 여러 유형의 예시 알림을 추가했다. 예시 데이터는 배포 데이터에 포함하지 않는다. 현재 서버에 저장된 알림 본문과 원본 링크를 표시하며 댓글 전문이나 변경 전후 값은 별도의 스냅샷 설계가 필요하다.

서버 check(178개 테스트 포함), OpenAPI 생성, 클라이언트 check(34개 테스트·구조 검사·타입·빌드)가 통과했다. 브라우저에서 사용자/시스템 아바타, 좌측 너비 조절·재방문 보존, 읽음 처리·배경 변화, 단독 상태 화면의 뷰포트 높이와 불필요한 스크롤 제거를 확인했다.
