# 상세 관계 흐름 (BIT-71·BIT-72·BIT-73)

기준: 0.11.0 이후 로컬 구현. 결정 D-100 / BIT-74.

## 화면과 동작

- 본문 아래 하위 작업(완료/전체·상태·참조 키·담당자), 연결된 문서/업무, 참조한 문서/역참조를 행 리스트로 제공한다. 표 머리·두꺼운 카드 없이 작은 접기 헤더와 토큰을 사용한다.
- 빈 상태는 간결한 안내와 추가 동작을 제공한다. 관계가 없을 때 여러 개의 큰 빈 그림으로 본문을 밀지 않는다.
- 관계 선택은 검색 다이얼로그에서 대상·프로젝트를 확인한 후 연결을 확정한다. 검색 중/실패/결과 없음·저장 중·실패를 구분한다. 취소는 변경 없이 닫고 원래 버튼에 초점을 돌린다.
- 새 하위 작업은 현재 프로젝트·부모 우선순위·시작 전 상태·미배정으로 원자적으로 생성한다. 기존 업무 연결도 지원한다. 연결 해제는 항목 삭제와 다르다.
- 문서 본문은 검색하여 ID 기반 링크를 삽입한다. 본문 참조와 직접 연결을 출처로 구분한다. 역참조를 편집 권한 없는 독자에게도 접근 가능한 범위에서 제공한다.
- 모바일에서는 제목이 줄어들 수 있고 보조 메타데이터는 아래 줄로 이동한다. 아이콘은 텍스트 토큰 크기를 따르며 조작은 키보드·터치로 가능해야 한다.
- Git 최신 상태는 기존 연결된 코드 영역, 변경 사건은 활동에 유지한다. 이번 작업은 Git 연동 동작을 바꾸지 않는다.

## 검증할 흐름

하위 생성·중복 부모·순환 차단·해제 후 항목 보존, 읽기 전용·타 프로젝트·타 워크스페이스 권한, 양방향 문서/업무 표시, 직접 연결과 본문 링크 공존·본문 제거·역참조·제목 변경·삭제·숨겨진 자료, 키보드 선택·취소·모바일 줄바꿈.

## Linear 실화면 기준 공통 상세 (BIT-75·BIT-76 / D-101·D-102)

로그인된 DEV-9에서 하위 작업·연결 문서·외부 링크·리액션·댓글을 만들고 데스크톱·390px을 비교했다. 최종 사용자 선택은 두 크기 모두 제목24px(모바일22px)·속성13px 칩·본문15px/24px·리액션·관계 목록·활동 순서다. 우측 속성 패널은 제거한다. 상위 작업은 제목 위의 짧은 맥락 줄이고, 하위 작업 생성은 인라인 입력이다. 작업과 문서는 DetailLayout과 detail-engagement를 공유한다.

제목·본문은 생성·수정 폼에서 편집하고 속성은 상세에서 즉시 변경한다. 폼의 중복 생성·편집 제목과 상세의 첨부 버튼은 제거한다. 파일은 본문 Markdown 블록으로 저장하고 드래그·Alt+위/아래·이동 버튼으로 순서를 바꾼다. 업로드·본문·대상의 생성/수정은 원자적으로 확정하며 실패하면 초안을 유지한다. 댓글도 같은 본문 첨부와 리액션을 사용한다.

## 프로젝트 선택·해제 (BIT-78 / D-103)

프로젝트 배지에서 선택하거나 해제한다. 해제 후 워크스페이스 상세 주소에서 기존 참조·본문·댓글·관계·리액션을 유지한다. 프로젝트 없는 작업은 기본 상태를 직접 변경할 수 있고 다시 연결할 때 상태 범주를 새 프로젝트 워크플로에 대응시킨다. 새 하위 작업과 새 반복 규칙은 프로젝트 선택 후 가능하다. 기존 반복 종료는 가능하다. 현재 로컬 구현이며 배포 기준으로 간주하지 않는다.


## 모바일 목록과 폼 후속 정리 (BIT-81·BIT-76)

여러 사람은 이름 없이 최대 세 아바타와 작은 +N으로 표시한다. 모바일 업무 목록은 아바타를 우측 끝에 두고 미배정 빈 원을 제거하며 제목은 한 줄 말줄임이다. 본문 첨부 버튼은 생성·수정 폼의 본문 아래/속성 구분선 위, 댓글 첨부는 입력창 하단 왼쪽에 둔다. 프로젝트 배지도 모바일 속성 배지와 같은 높이·글자 크기로 표시한다.

## 검증 결과

서버 check(단위·계약 55개, 통합 133개), 클라이언트 check(36개 테스트·컴포넌트/FSD 린트·타입·빌드)를 통과했다. 1440px·390px에서 속성 칩, 직접 변경, 관계·하위 생성, 프로젝트 해제 후 편집·재연결, 본문 파일의 드래그·버튼 이동 및 저장·재조회, 첨부 댓글 전송을 확인했다. V26은 기존 로컬 데이터 백업 후 적용하여 기존 행 수·integrity_check·foreign_key_check를 확인했다. 운영 DB에는 아직 적용하지 않았다.
