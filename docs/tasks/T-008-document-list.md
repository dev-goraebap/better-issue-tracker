# 문서 혼합 리스트와 공유 지정 순서

업무 BIT-57, 결정 D-097 / BIT-58. 로컬 검토를 마쳤으며 사용자가 커밋·PR·운영 배포를 승인했다. 로컬 예시 데이터는 운영으로 이전하지 않는다.

## 사용자가 정한 것

- SDLC 폴더 이름에 숫자 접두어를 붙이지 않는다.
- 데스크톱도 테이블 대신 하나의 리스트로 표현한다. 공통 정보와 유형별 메타데이터를 오른쪽에 배치한다.
- 왼쪽 핸들로 위치를 지정하고 정렬 방법 중 하나로 선택한다.
- 지정 순서는 폴더별 공유 값이다. 쓰기 가능한 멤버가 변경하며 버전 충돌은 거절한다.

## 화면과 동작

`FolderList`가 프로젝트·폴더·문서를 같은 행으로 표현한다. 기본은 지정 순서이며 이름순·최근 변경순과 각각의 방향은 URL에 보존한다. 검색·유형·라벨 필터도 URL에 둔다. 보이지 않는 항목의 순서를 실수로 바꾸지 않도록 재배치는 전체 항목이 보이는 지정 순서에서만 가능하다. 포인터 드래그와 Alt + 위/아래 화살표, Escape 취소는 기존 `useRowReorder`를 재사용한다.

`V20__document_order.sql`과 `PUT /documents/order`로 현재 위치의 혼합 순서를 저장한다. 문서 본문의 버전과 별도로 순서 버전을 검사한다. 다른 멤버의 숨겨진 프로젝트는 서버가 보존한다. `contents` 응답의 `ordering`으로 저장된 순서와 버전을 읽는다.

## 로컬 콘텐츠

기존 개발 DB를 백업한 뒤 확인 프로젝트에 `프로젝트 안내`, `기획·요구사항`, `아키텍처`, `상세 설계`, `검증`, `배포·운영` 폴더 6개와 문서 지도·arc42 등 예시 문서를 추가했다. 워크스페이스 공통 가이드도 추가해 프로젝트·폴더·문서의 혼합 표현을 확인한다. 예시 데이터는 로컬 DB에만 있고 소스에 운영 데이터나 자격 증명을 넣지 않는다.

## 확인

- 서버 통합 검사: 혼합 순서 저장·공유 조회·폴더별 분리, 오래된 버전 409, 다른 폴더·누락·중복 400, 읽기 멤버 쓰기 403.
- 화면: 포인터 드래그, Alt + 화살표, 새로고침 후 순서 유지, 이름순 전환·초기화, 유형과 라벨 복합 필터.
