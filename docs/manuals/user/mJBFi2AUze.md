# 계정 보안·API 키·에이전트 연결

비밀번호와 API 키는 내 계정으로 접근하는 수단입니다. 업무 댓글이나 매뉴얼에 비밀값을 붙여 넣지 않습니다.

## 로그인과 비밀번호 관리

1. **내 설정 → 시큐리티**에서 비밀번호와 로그인 종료 동작을 확인합니다.
2. 비밀번호 변경에는 현재 비밀번호와 새 비밀번호 확인이 필요합니다.
3. 변경 뒤 다른 기기의 로그인과 기존 API 키가 무효화되므로 사용하는 연동을 점검합니다.
4. 모든 기기에서 로그아웃하는 동작은 현재 기기도 포함합니다. 다시 로그인할 준비를 하고 사용합니다.

![비밀번호와 로그인 종료를 관리하는 시큐리티](attachment:StYoH4lN9F)

새 비밀번호는 15~64자이면서 UTF-8 72바이트 이하입니다. 임시 비밀번호로 로그인해 변경을 요구받았다면 먼저 변경합니다. 비밀번호를 잊었다면 인스턴스 관리자에게 복구를 요청합니다.

## API 키 만들기

1. **내 설정 → API 키**에서 추가 동작을 누릅니다.
2. 용도를 알 수 있는 이름을 적고, 에이전트 이름과 만료 기간을 정합니다.
3. 현재 비밀번호로 본인 확인 후 생성합니다.
4. 처음 표시되는 키를 안전한 위치에 저장합니다. 전체 키는 다시 표시되지 않으므로 잃어버렸다면 기존 키를 폐기하고 새 키를 만듭니다.

![키 이름·에이전트 이름·만료와 본인 확인 입력](attachment:pt9MwOPrzK)

이름과 에이전트 이름은 최대 64자입니다. 키는 사용자 자신의 워크스페이스 권한을 따르며, 역할이 줄어들면 키의 권한도 줄어듭니다. 키를 만들었다고 소유자 권한을 따로 얻는 것은 아닙니다. 계정 보안과 초대 등 본인 로그인이 필요한 동작은 API 키만으로 수행할 수 없습니다.

## 에이전트에서 BIT 사용하기

화면의 **Agent** 연결 안내에서 자신의 도구에 맞는 서버 주소와 인증 설정을 확인합니다. 키는 로컬 비밀 설정에 넣고, 워크스페이스가 여러 개라면 작업할 워크스페이스와 프로젝트를 명확히 지정합니다. 에이전트 이름을 구분해 두면 활동에서 사람과 에이전트의 변경을 구별하기 쉽습니다.

사용하지 않는 키는 폐기합니다. 유출이 의심되면 즉시 키를 폐기하고 필요한 경우 로그인 세션도 종료합니다. 연결 오류는 서버 주소·키 만료·현재 역할부터 확인합니다.
