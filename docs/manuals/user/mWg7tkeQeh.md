# 프로젝트 워크플로와 저장소 연동

프로젝트의 상태 칸과 Git 저장소 이벤트를 맞추면 업무 진행을 일관되게 관리할 수 있습니다. 워크스페이스 설정 권한이 있는 사용자가 프로젝트 관리에서 설정합니다.

## 워크플로 칸 정하기

1. 프로젝트를 열고 **프로젝트 관리 → 워크플로**로 이동합니다.
2. 칸의 이름과 의미를 확인하고 필요한 칸을 추가합니다.
3. 이름만 아니라 상태 범주와 완료 의미를 확인합니다.
4. 손잡이를 끌어 순서를 바꿉니다. 변경 뒤 진행 보드의 배치와 상태 선택을 확인합니다.

![프로젝트 상태 칸과 순서 관리](attachment:zdMXHJsh8E)

같은 진행 중 범주에 ‘진행 중’, ‘검토 중’처럼 여러 칸을 둘 수 있습니다. 칸 이름이 비슷하더라도 완료 칸과 취소 칸은 다른 의미입니다. 업무가 남은 칸을 없앨 때는 이동 대상 등 화면 안내를 확인합니다.

## 저장소 연결하기

1. **저장소 연동**을 엽니다. 지원하는 GitHub·GitLab·Gitea 중 사용하는 호스트를 선택합니다.
2. 주소, 저장소 경로, 접근 토큰을 입력합니다. 저장소는 `owner/repository` 또는 GitLab의 `group/project` 형식이며 주소를 붙여 넣을 수도 있습니다.
3. 연결 창에 안내된 토큰 권한과 대상 호스트를 확인하고 **연결하기**를 누릅니다.
4. 연결 결과의 웹훅 상태를 확인합니다. 자동 등록되지 않았다면 화면의 주소·비밀값과 이벤트 안내로 저장소에 직접 등록하고 수신을 확인합니다.

![연결할 Git 호스트를 고르는 저장소 연동 화면](attachment:qxWeNAn1Vw)

![저장소 경로와 접근 토큰을 입력하는 연결 창](attachment:D4JRZkp1Ov)

토큰은 댓글이나 문서 본문에 적지 않습니다. 연결 시 서버가 저장소와 토큰을 확인하므로 잘못된 경로·만료·권한 부족이면 안내를 따라 고칩니다. 저장소에 남기는 업무와 댓글은 연결 토큰 계정으로 표시될 수 있습니다.

## 이벤트별 이동 규칙

브랜치 업로드, PR/MR 열기·병합, 저장소 이슈 열기·닫기에 대해 **기본**, 특정 칸, **옮기지 않음**을 정합니다. 브랜치 이름의 `web-8-...`처럼 업무 키를 포함하거나 PR/MR에 관련 업무를 명시해 연결합니다. 기본 규칙도 이미 완료·취소된 업무를 무조건 다시 열지는 않습니다.

BIT는 저장소를 호스팅하지 않습니다. 연결 기능이 꺼진 환경에서는 해당 기능만 사용할 수 없으며 이슈와 문서 작업은 계속할 수 있습니다. 외부 호스트의 토큰 발급·웹훅 화면은 호스트의 안내를 함께 확인합니다.

연결 뒤 **저장소 이슈와 동기화**를 켜면 제목·설명·속성·댓글을 서로 반영합니다. 끄면 브랜치·PR·커밋 연결만 남습니다. 기존 열린 이슈 가져오기, 연결 알림 댓글, 토큰 교체와 연결 해제는 연결 카드의 해당 동작을 사용합니다. 토큰이 만료되면 **토큰 바꾸기**로 교체하고 최근 오류와 마지막 웹훅 수신 시각을 확인합니다.

상태 이름은 필수 최대 32자입니다. **완료 상태**를 켜면 업무가 닫히는 칸이 되며, 취소 범주는 항상 닫힌 상태입니다. 완료 여부를 바꾸면 분류 선택도 그 의미에 맞춰 제한됩니다.
