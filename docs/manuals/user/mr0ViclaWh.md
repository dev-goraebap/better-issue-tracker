# 역할과 권한 이해하기

역할은 워크스페이스에서 볼 수 있는 내용과 바꿀 수 있는 내용을 정합니다. 프로젝트 참여 지정은 담당 팀을 표시하는 기능이며, 워크스페이스 역할과는 다릅니다.

## 기본 역할

| 할 수 있는 일 | 보기 전용 | 멤버 | 관리자 | 소유자 |
| --- | --- | --- | --- | --- |
| 이슈·일정·매뉴얼·리소스 조회 | 가능 | 가능 | 가능 | 가능 |
| 이슈·일정 작성·수정 | — | 가능 | 가능 | 가능 |
| 매뉴얼·문서·폴더 작성·수정 | — | 가능 | 가능 | 가능 |
| 라벨 관리 | — | 가능 | 가능 | 가능 |
| 프로젝트 생성·설정·워크플로 관리 | — | — | 가능 | 가능 |
| 멤버 초대·역할 관리 | — | — | 가능, 대상 제한 있음 | 가능 |
| 워크스페이스 설정 변경 | — | — | 가능 | 가능 |
| 워크스페이스 삭제·소유권 이전 | — | — | — | 가능 |

![워크스페이스 관리의 기본 역할 비교표](attachment:WyQj3bx9if)

보기 전용 사용자는 내용을 읽고 제공되는 내보내기 도구를 사용할 수 있지만 이슈 생성·본문 편집·댓글 작성·매뉴얼 의견 해결 등의 변경은 할 수 없습니다. 버튼이 없으면 먼저 자신의 역할을 확인합니다.

## 사용자 정의 역할

관리자는 **워크스페이스 관리 → 역할 → 역할 추가**에서 필요한 권한만 묶을 수 있습니다. 예를 들어 문서 작성 권한만 주는 **문서 편집자**를 만들 수 있습니다. 사용자 정의 역할은 기본 멤버 권한에 더해지는 방식이 아니라, 선택한 권한을 기준으로 적용됩니다. 조회 권한은 기본으로 포함되고 소유자 권한은 사용자 정의 역할로 부여할 수 없습니다.

![권한을 선택해 사용자 정의 역할을 만드는 창](attachment:uh5iipc68y)

자신이 가진 범위를 넘는 권한을 다른 사람에게 부여할 수 없습니다. 기본 역할에서 관리자는 다른 관리자나 소유자를 변경·내보낼 수 없으며, 관리자 역할 부여는 소유자가 담당합니다. 자신의 역할이나 소유자 역할은 일반 멤버의 역할 변경 메뉴로 바꾸지 않습니다.

## 프로젝트 멤버와 접근 권한의 차이

프로젝트에 참여자로 지정되지 않았더라도 워크스페이스의 조회 권한이 있으면 프로젝트를 볼 수 있습니다. 프로젝트 멤버에서 제외해도 워크스페이스 멤버 자격과 역할은 유지됩니다. **특정 사람에게 프로젝트를 숨기는 기능으로 사용하지 마세요.**

역할 변경은 워크스페이스 전체에 적용되고 그 사용자의 API 키 권한에도 반영됩니다. 실제 변경 방법은 [멤버 관리](mIsWmIWzmE.md)를 참고합니다.

역할 이름은 필수이며 최대 64자입니다. 권한 선택 뒤 역할을 만들고, 멤버 화면에서 실제 대상에게 부여해야 적용됩니다. 이름만 만들었다고 기존 멤버의 권한이 바뀌지는 않습니다.
