# 확정 결정과 현재 구조 연결하기

이 장은 중요한 선택을 찾는 색인입니다. 결정의 정본은 `docs/decisions.md`이며, 관련 BIT 업무에는 같은 D-번호를 남깁니다. 여기에서 독립된 결정 원문을 다시 유지하지 않습니다.

| 결정 | 현재 구조에 미치는 영향 |
| --- | --- |
| D-021·D-022·D-081 | 사람의 API 키 주체·에이전트 감사와 서버 내 MCP |
| D-029·D-030 | 저장소 어댑터와 선택 기능 비활성 경계 |
| D-098·D-125 | 기존 운영 문서 읽기를 유지하되, 현행 매뉴얼 원본은 저장소에서 읽고 BIT에는 게시 |
| D-106 | 데스크톱 이슈 행 리스트와 뷰 그룹 기준 |
| D-114 | 선택은 해당 업무의 결정 댓글로 연결 |
| D-116·D-117·D-118 | 범위별 메뉴·프로젝트 포커스·일정 달력 |
| D-119 | 책 단위 서버 저장·버전·이미지 소유권 |
| D-120·D-121 | 사용자 매뉴얼 품질과 사용하는 프로젝트의 갱신 |
| D-122·D-123 | 두 매뉴얼을 연결하고 설계 규칙·코드 예·검증 기준은 횡단 관심사에 집중 |

| D-124·D-125 | 저장소별 스킬 진입점과 저장소 원본 → BIT 게시본, 풍부한 블록 변환 계약 |

## 새 판단을 기록할 때

6개월 뒤 ‘왜 이렇게 했지?’가 될 선택이면 무엇을·왜·검토한 대안을 원본에 기록합니다. 구현 현황이나 일회성 검사 로그는 결정이 아니라 업무 결과입니다. 예전 결정과 충돌하면 대체 관계를 분명히 하고 조용히 과거 원문을 바꾸지 않습니다.

구현 중 업무·브랜치·커밋 연결은 [협업 절차](../development/aTEd5efrEQ.md), 기록 유지 방법은 [문서와 스킬](../development/pNDA17FCoQ.md)을 따릅니다.

## 근거와 적용 기준

앱 버전은 server/build.gradle과 client/package.json 기준 0.22.0입니다. 개발 커밋은 출시 버전과 구분합니다. 근거 링크는 현재 체크아웃의 원본이며, 실제 코드 발췌는 공백을 정규화해 대조했습니다. 실행 검사 이력은 BIT-148을 따르며 이 정적 검수는 새 실행/화면 검증을 뜻하지 않습니다.
