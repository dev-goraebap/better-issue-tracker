# 드래그 정렬·키보드·실패 회복

사용자가 목록·섹션·메뉴의 저장 순서를 바꾸는 기능에 적용합니다.

## 규칙과 이유

공용 useRowReorder와 손잡이·상태 읽기를 사용합니다. 드래그뿐 아니라 Alt+위/아래, Escape 취소, 실패 시 저장된 순서 복원을 확인합니다. 화면에 일부만 보이는데 전체 ID 순서를 보내지 않습니다.

## BIT 실제 코드

현재 코드 발췌: `client/src/pages/workspace/projects/ui/ProjectsPage.tsx` · 56행부터. 주변 선언·호출부는 원본에서 확인합니다.

```tsx
  const canOrder = canManage && tab === 'active' && !search.q && !result.hasNextPage && rows.length > 1;
  const reorder = useRowReorder(rows, { word: '프로젝트', object: '프로젝트를', topic: '프로젝트는' }, `${moving.ghost} ${styles.projectGhost}`, async order => {
    setError('');
    try { await reorderProjects(workspaceId, order); }
    finally { await refreshProjects(client, workspaceId); }
  }, failure => setError(authError(failure)));
```

관리 권한·진행 중·검색 없음·다음 페이지 없음·두 행 이상일 때 순서 조작을 제공합니다. 전송 뒤에는 최신 프로젝트를 읽고 실패는 안내합니다. 이 조건은 프로젝트 전체 순서 계약의 예이며 모든 목록에 똑같이 복사하지 않습니다.

## 피해야 할 예

아래는 실패 이유를 보여 주는 설명용 반례이며 현재 BIT 구현의 발췌가 아닙니다. 생략된 선언이 있어 그대로 실행하는 완성 코드가 아닙니다.

```tsx
// 필터로 일부 행만 있는데 전체 순서 API로 보내는 반례
await reorderProjects(workspaceId, visibleRows.map(row => row.id));
// 위/아래 전용 버튼만 새로 만드는 대신 공용 순서 조작 사용
```

## 예외와 적용 한계

보드 카드 이동·날짜 드래그는 다른 도메인 의미를 가집니다. 공용 행 순서 변경을 억지로 적용하지 않습니다. 매뉴얼 구조 편집은 섹션 소속과 페이지 순서가 함께 바뀌므로 모든 ID와 목적지의 일치도 검사합니다.

## 검증 기준

자동: `npm run lint:reorder --prefix client`, row-order/manual-order 테스트를 실행합니다.

화면: 손잡이 포커스·Alt+이동·드래그·Esc·저장 거절·연속 이동·스크롤 가장자리·reduced motion을 확인합니다. 순서 계산 테스트는 실제 포인터 위치와 보조기기 읽기를 대체하지 않습니다.
