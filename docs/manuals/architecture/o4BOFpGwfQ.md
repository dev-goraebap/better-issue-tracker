# 제품 목적과 아키텍처 목표

BIT는 사람과 에이전트가 업무·결정·근거·코드를 같은 흐름에서 읽는 셀프호스팅 경량 ALM입니다. Git 호스팅을 새로 만들지 않고 외부 저장소를 참조합니다. 이 책은 arc42의 12영역으로 현재 구조와 선택의 이유를 설명합니다. 실행·변경 작업 순서는 [개발 매뉴얼](../development/zAhysBXYMY.md), 화면 사용법은 [사용자 매뉴얼](https://bit.goraebap.xyz/workspaces/s9eYqb2Aqz/projects/wyuo6Iro9D/manuals?manual=qwohgB4f9d)에 있습니다.

## 이해관계자와 필요한 정보

| 독자 | 해결할 질문 | 구조에 미치는 영향 |
| --- | --- | --- |
| 업무를 맡는 사람 | 해야 할 일과 이유, 참고 자료를 어디서 찾는가? | 범위별 탐색과 관계·댓글·자료 연결 |
| 에이전트 | 같은 권한으로 무엇을 읽고 변경할 수 있는가? | REST와 MCP가 같은 서비스·권한을 사용 |
| 개발자 | 어디를 바꾸고 어떤 계약을 지켜야 하는가? | 모듈 공개 계약, 페이지 중심 화면 배치 |
| 운영자 | 외부 서비스 없이 실행하고 데이터를 보존할 수 있는가? | 단일 이미지, SQLite·파일 볼륨, 선택 어댑터 |

## 우선하는 품질 목표

첫째, 다른 진입점으로 접근해도 권한과 변경 규칙이 같아야 합니다. 둘째, 외부 설정이 없어도 기본 업무를 사용할 수 있어야 합니다. 셋째, 사람이 다음 변경의 이유를 찾을 수 있어야 합니다. 넷째, 작은 서버에서도 운영·백업 경로를 이해할 수 있어야 합니다. 각 목표의 확인 가능한 시나리오는 [품질 요구사항](wSwn4EnNhp.md)에 있습니다.

실시간 공동 편집·공개 위키·결재·Git 저장소 호스팅은 이 구조가 현재 제공한다고 약속하는 범위가 아닙니다. 코드에 남아 있는 모듈 이름과 제품 메뉴도 일대일 대응하지 않습니다.

## 이 책을 쓰는 방법

설계 변경은 범위·구성 요소·실행 흐름을 함께 보고, 구현할 때 [개발 작업 길잡이](../development/zAhysBXYMY.md)로 이동합니다. 앱 구현 기준은 v0.22.0입니다. 문서의 제안이나 품질 목표를 이미 성능으로 입증된 사실로 해석하지 않습니다.

## 근거와 적용 기준

앱 버전은 server/build.gradle과 client/package.json 기준 0.22.0입니다. 개발 커밋은 출시 버전과 구분합니다. 근거 링크는 현재 체크아웃의 원본이며, 실제 코드 발췌는 공백을 정규화해 대조했습니다. 실행 검사 이력은 BIT-148을 따르며 이 정적 검수는 새 실행/화면 검증을 뜻하지 않습니다.
