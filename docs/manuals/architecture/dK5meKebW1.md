# 문제를 구조로 해결하는 방식

BIT는 외부 도구를 더 연결하는 것만으로 맥락 전달 문제를 해결하지 않습니다. 사람이 읽는 업무와 에이전트가 읽는 API/MCP가 같은 데이터·권한·변경 규칙에 도달하도록 구성합니다.

| 문제 | 채택한 접근 | 대가와 주의점 |
| --- | --- | --- |
| 화면과 에이전트의 규칙이 달라짐 | 모듈 서비스에 공통 권한·변경 규칙 | 진입점 검증만으로 충분하지 않음 |
| 작은 배포에 운영 구성요소가 많아짐 | 모듈형 모놀리스·SQLite·단일 이미지 | 쓰기 경합과 단일 인스턴스 한계 |
| 외부 설정 때문에 기본 업무도 막힘 | 포트/어댑터·capabilities | 꺼진 경우와 켜진 경우 각각 확인 필요 |
| 모든 문서 기능이 한 모델로 커짐 | 리소스와 매뉴얼을 별도 수명주기로 분리 | 자료 간 링크와 소속 경계를 명확히 해야 함 |
| 같은 책을 덮어쓰며 편집 손실 | 책 단위 버전 검사·원자적 저장 | 서로 다른 페이지 편집도 충돌할 수 있음 |
| 화면마다 디자인이 달라짐 | 공용 프레임·목록·토큰·순서 조작 재사용 | 부품 검사만으로 실제 배치 완성도는 보장 못함 |

## 이 전략이 구현되는 위치

[구성 요소](j83U7eq671.md)는 책임 분할을, [실행 흐름](v1fxXxJWn3.md)은 서비스 공유를, [공통 개념](tIv5Msv7KG.md)은 계층과 트랜잭션 경계를 설명합니다. 구체적인 작업 순서는 [개발 매뉴얼](../development/zAhysBXYMY.md)에 둡니다.

이 표는 현재 채택한 구조를 요약한 것입니다. 새로운 CQRS 저장소·메시지 브로커·마이크로서비스를 도입하자는 지시가 아닙니다. 과거 선택의 원문과 맥락은 [결정 원본](xBqefUiRin.md)으로 연결합니다. 문서 구조는 [arc42 공식 개요](https://arc42.org/overview/)를 적용했습니다.

## 근거와 적용 기준

앱 버전은 server/build.gradle과 client/package.json 기준 0.22.0입니다. 개발 커밋은 출시 버전과 구분합니다. 근거 링크는 현재 체크아웃의 원본이며, 실제 코드 발췌는 공백을 정규화해 대조했습니다. 실행 검사 이력은 BIT-148을 따르며 이 정적 검수는 새 실행/화면 검증을 뜻하지 않습니다.
